# Consolidate

월 1회. 낱개 캡처를 **다음에 다시 꺼내 쓸 수 있는 형태**로 승격시킵니다.

캡처 → 주간 분석 → 월간 통합 → 다시 캡처. 이 루프가 이 시스템이 "자기진화"라 부르는 것의 실체입니다. 가중치를 학습하지 않습니다. 파일 위에서 도는 예약된 반성 루프일 뿐이고, 그게 전부입니다 — 다만 보통 무너지는 부분(유지보수)을 에이전트가 대신 맡습니다.

## 승격 기준

노트 뭉치가 아래를 **모두** 만족할 때만 프레임워크로 올립니다.

1. 서로 다른 3개 이상의 노트가 같은 주제를 다룬다
2. 그 주제가 2주 이상에 걸쳐 반복 등장했다
3. 일반화했을 때 **다음번 상황에 실제로 적용 가능**하다

3번이 관문입니다. "AI 에이전트에 대해 여러 번 썼다"는 프레임워크가 아닙니다. "에이전트 시스템에서 비싼 모델은 판단에만 쓰고 I/O는 싼 모델로 라우팅한다"는 프레임워크입니다.

**기준에 못 미치면 승격하지 마세요.** 통합할 게 없는 달은 없다고 보고하는 게 맞습니다.

## 절차

### 1. 후보를 찾는다

전체 vault에서 태그·wikilink·반복 어휘로 군집을 만듭니다. 각 군집을 위 3기준으로 채점합니다.

### 2. 프레임워크를 쓴다

`03-resources/frameworks/<이름>.md`:

```markdown
---
title: <프레임워크 이름 — 명사구>
date: <오늘>
domain: resources
tags: [framework, <주제>]
summary: <언제 이걸 꺼내 쓰는지 한 문장.>
source: consolidate
---

## 언제 쓰나
<이 프레임워크를 꺼내야 하는 상황. 구체적인 트리거로.>

## 핵심
<3~5개 항목. 각각 명령형 한 문장 + 근거 한 줄.>

## 하지 말 것
<이 프레임워크가 적용되지 **않는** 경우. 이 섹션이 프레임워크를 쓸모 있게 만듭니다.>

## 근거가 된 노트
- [[노트]] — 여기서 무엇을 가져왔는지
```

### 3. 원본을 보존한다

원본 노트는 **삭제하지 않습니다.** 프레임워크로의 `[[링크]]`를 원본 하단에 추가만 합니다. 통합은 요약이지 대체가 아닙니다.

### 4. 아카이브한다

12개월 이상 손대지 않았고 어떤 노트도 링크하지 않는 노트는 `04-archive/`로 옮길 것을 **제안**합니다. 이동은 사용자 승인 후에.

## 마지막에 보고할 것

승격한 프레임워크, 기준에 못 미쳐 보류한 군집(그리고 어느 기준에서 걸렸는지), 아카이브 제안 목록.
