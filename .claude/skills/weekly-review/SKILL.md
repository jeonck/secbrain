# Weekly Review

일일 캡처가 주간 분석을 먹이고, 주간 분석이 월간 통합을 먹입니다. 이 스킬은 그 가운데 고리입니다.

**핵심은 요약이 아니라 교차 참조입니다.** 한 주 노트를 다시 나열하는 건 아무 가치가 없습니다 — 사용자는 이미 그걸 썼습니다. 가치는 *서로 다른 폴더에 흩어져서 사용자가 놓친 연결*에 있습니다.

## 절차

### 1. 한 주를 모은다

`date`가 최근 7일인 모든 노트. 폴더 무관.

### 2. 패턴을 찾는다

찾을 것:

- **반복** — 서로 다른 노트에 다른 표현으로 3회 이상 나온 주제. 대개 사용자가 아직 이름 붙이지 못한 문제입니다.
- **도메인 교차** — `01-projects/`의 문제와 `03-resources/`에 저장해 둔 자료가 사실 같은 것을 가리키는 경우. 이게 가장 값진 발견입니다.
- **정체** — 지난주에 열렸는데 이번 주 언급이 없는 태스크.
- **마감 임박** — `📅` 날짜가 앞으로 7일 안인 미완료 태스크.
- **모순** — 사용자가 화요일에 쓴 것과 금요일에 쓴 것이 어긋나는 지점. 조심스럽게, 판단 없이 제시합니다.

**억지로 만들지 마세요.** 패턴이 두 개뿐이면 두 개만 씁니다. 다섯 개를 채우려고 약한 연결을 끼워 넣는 순간 이 리뷰는 신뢰를 잃습니다.

### 3. 쓴다

`05-daily/YYYY-MM-DD-weekly.md` (그 주 일요일 날짜):

```markdown
---
title: 위클리 리뷰 2026-07-26 ~ 2026-08-01
date: 2026-08-01
domain: daily
tags: [review, weekly]
summary: <이번 주의 한 문장. 발견된 패턴 중 가장 중요한 것.>
source: weekly-review
---

## 이번 주 숫자
- 새 노트 N개 (projects N · areas N · resources N · inbox N)
- 완료한 태스크 N / 새로 생긴 태스크 N
- 손대지 않은 도메인: <있으면>

## 발견한 패턴

### <패턴 이름 — 사용자가 쓰지 않은 표현으로>
<무엇이 반복되는지. 근거로 [[노트1]], [[노트2]], [[노트3]] 를 겁니다.>
<이게 뜻하는 바에 대한 가설 한 문장. 단정하지 말 것.>

## 도메인을 가로지른 연결
<A 폴더의 X와 B 폴더의 Y가 같은 것을 가리킨다. 왜 그렇게 보는지.>

## 정체된 것
- [[노트]] — 7/22 이후 언급 없음. 아직 유효한가?

## 다음 7일 마감
- [ ] <태스크> 📅 2026-08-04 — [[출처-노트]]

## 이번 주 답하지 못한 질문
<노트에 물음표로 남아 있는데 아직 해소되지 않은 것.>
```

### 4. inbox를 비운다

`00-inbox/`에 7일 이상 머문 노트를 검토해 갈 곳을 제안합니다. **직접 옮기지는 마세요** — 리뷰에 제안으로 적고 사용자가 결정합니다.

## 마지막에 보고할 것

패턴 개수, 가장 강한 연결 하나, **정체된 태스크 수**.
