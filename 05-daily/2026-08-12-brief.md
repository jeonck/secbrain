## 오늘 하나만 본다면

2026-08-07 Claude Code v2.1.224에서 독립적으로 실행 중인 세션끼리 서로를 찾아 메시지를 주고받는 기능이 들어왔습니다 — `ListAgents`로 실행 중인 세션을 찾고 `SendMessage`로 텍스트를 보냅니다. 같은 기기(macOS/Linux)에서는 유닉스 도메인 소켓으로, 다른 기기 간에는 Remote Control을 통해 Anthropic 인프라를 거칩니다. 메시지는 텍스트만 담고 명령을 실행할 수 없으며, `bypassPermissions` 세션으로 들어오는 메시지는 기본적으로 사용자 승인 대기(5분 만료) 상태가 됩니다. 이 리포트를 쓰고 있는 이 세션 자체가 `ListAgents`/`SendMessage` 도구를 쓰는 환경이라는 점에서, [[cog-architecture]]가 말하는 "리드가 판단, 워커가 I/O" 패턴을 넘어 **세션 간 조율**이라는 새 축이 실제로 쓸 수 있는 기능이 됐다는 뜻입니다.

## agents

### Claude Code 세션 간 메시징 (SendMessage/ListAgents) — v2.1.224
독립 실행 중인 Claude Code 세션들이 서로를 발견(`ListAgents`)하고 텍스트 메시지를 주고받는(`SendMessage`) 기능이 Team/Enterprise 플랜에 추가됐습니다. 같은 기기에서는 소켓 통신, 기기 간에는 Remote Control 경유이며 대화 이력이나 파일은 전달되지 않습니다. Windows는 미지원입니다.

- 출처: [anthropics/claude-code CHANGELOG.md](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md) (v2.1.224, GitHub 릴리스 태그 2026-08-07) · 2026-08-07
- 신뢰도: 높음 (공식 리포지토리 CHANGELOG + 릴리스 태그)
- 왜 중요한가: 이 브리프를 쓰는 세션이 바로 이 도구(ListAgents/SendMessage)를 쓰는 환경입니다. [[secbrain-site]] 파이프라인이 이슈 → Actions → Claude Code 단일 세션 구조인데, 세션 간 메시징이 있으면 향후 "브레인덤프 세션이 daily-brief 세션에 완료를 알린다" 같은 조율이 인프라 추가 없이 가능해집니다.

### Claude apps 게이트웨이 지출 상한 — v2.1.225 사용량 경고 개선
자체 게이트웨이를 운영하는 조직이 개발자·그룹·조직 단위로 일/주/월 지출 상한을 걸고 Admin API로 관리하는 기능이 이미 있었는데, v2.1.225(2026-08-08)부터 상한 도달 시 Claude Code가 보여주는 메시지에 상한값·리셋 시각·운영자 메시지가 함께 표시되도록 개선됐습니다. 75%·95% 지점에서 사전 경고도 뜹니다.

- 출처: [Claude apps gateway spend limits — Claude Code Docs](https://code.claude.com/docs/en/claude-apps-gateway-spend-limits) · 확인일 2026-08-12 (v2.1.225 반영, 릴리스 2026-08-08)
- 신뢰도: 높음 (공식 문서 + CHANGELOG 교차 확인)
- 왜 중요한가: [[2026-08-10-에이전트-비용-구조-정리와-빈틈]]이 "모델 라우팅 말고는 vault에 비용 절감 기법이 없다"고 짚은 빈틈에 대한 또 다른 답 — 이번엔 Managed Agents의 세션 budget이 아니라, 게이트웨이 레벨에서 사용자·그룹별 하드 캡을 거는 방식입니다. 자체 게이트웨이를 두지 않는 이 vault엔 직접 적용되진 않지만, "상한을 어디 레벨에 걸 것인가"의 세 번째 사례로 기록해둘 만합니다.

## anthropic

### Fable 5 생물학 안전장치 재조정 — 오탐 최대 85% 감소
Anthropic이 Fable 5의 생물학 관련 안전장치 분류기를 다시 학습시켜, 정당한 질문까지 과도하게 차단되던 문제를 줄였습니다. 내외부 전문가 피드백을 받아 "무엇이 위험한가"를 정의하는 constitution을 다시 쓰고, 새 학습 데이터로 분류기를 재훈련했습니다. 생물학 관련 폴백이 제품 전반에서 약 85% 줄었고(Claude.ai 67%, Cowork 55%, Claude Code 17%, Claude Platform 7%), 바이러스학·독성학·분자 설계 같은 이중용도 영역은 계속 Opus 5로 폴백됩니다.

- 출처: [Improving Fable 5's Biology Safeguards — Anthropic](https://www.anthropic.com/news/improving-fable-5-s-biology-safeguards) · 2026-08-07
- 신뢰도: 높음 (Anthropic 공식 뉴스룸, 1차 출처)
- 왜 중요한가: 안전장치를 "차단 여부"가 아니라 "분류기 재훈련으로 오탐률을 낮춘다"는 구체적 수치로 보여준 사례라, 향후 이 vault에서 자동화 파이프라인의 오탐/과차단 문제를 다룰 때 참고할 만한 방법론입니다.

## devtools

### Claude Code 셀프호스팅 환경 — 퍼블릭 베타
Claude Code 세션을 Anthropic 인프라가 아니라 조직 자체 서버(온프레미스/사내 네트워크)에서 실행할 수 있게 됐습니다. Team/Enterprise 플랜 대상, 기본 꺼짐. `claude self-hosted-runner` 명령으로 자체 머신을 컴퓨트 레이어로 전환하며, 저장소 체크아웃·빌드 산출물·시크릿은 조직이 관리하는 머신에 남고 대화 트랜스크립트만 추론을 위해 Anthropic으로 전송됩니다.

- 출처: [Self-Hosted Environments for Claude Code — Anthropic](https://claude.com/blog/run-claude-code-sessions-on-your-own-compute) · 2026-08-06
- 신뢰도: 높음 (공식 블로그, 1차 출처)
- 왜 중요한가: `devtools` 키의 정의인 "로컬 우선(local-first) 소프트웨어"에 정확히 들어맞는 사례 — 클라우드 에이전트를 로컬/사내 인프라로 되가져오는 방향성입니다. [[secbrain-site]]는 GitHub Actions 러너에서 실행되는 구조라 직접 관련은 없지만, "에이전트 실행 위치를 누가 통제하는가"라는 같은 질문을 다른 방식으로 풀고 있습니다.

### GitHub Copilot Agent Plugins 1.0 — VS Code·CLI·앱 공용 플러그인 포맷
GitHub Copilot이 VS Code, Copilot CLI, Copilot 앱에서 공통으로 쓰는 플러그인 포맷 "Agent Plugins 1.0"을 냈습니다. 에이전트·스킬·훅·통합을 하나의 설치 가능한 패키지로 묶으며, CLI로 설치한 플러그인을 VS Code가 자동으로 인식합니다.

- 출처: [GitHub Changelog — Agent Plugins 1.0 in VS Code, Copilot CLI, and the Copilot app](https://github.blog/changelog/) · 2026-08-12
- 신뢰도: 중간 (GitHub 공식 changelog, 세부 스펙 문서는 별도 확인 필요)
- 왜 중요한가: 같은 날 Claude Code도 v2.1.229에서 로컬 소스를 지원하는 플러그인 마켓플레이스 커맨드를 추가했습니다(CHANGELOG.md 기준). 두 CLI 에이전트 진영이 같은 주에 "플러그인을 여러 표면(터미널/IDE/앱)에서 공유"하는 방향으로 수렴하고 있다는 신호입니다.

## pkm

### Notion Admin API — 에이전트 관리 엔드포인트 확장
Notion Admin API가 크레딧 사용량·한도·권한·상태·생성 정책·워크플로 메타데이터를 다루는 "에이전트 관리" 엔드포인트를 새로 포함하도록 확장됐습니다. Notion이 최근 연 Developer Platform(코드로 데이터 동기화·에이전트 도구를 만드는 Workers)의 관리 계층입니다.

- 출처: [Notion Developer Changelog](https://developers.notion.com/page/changelog) · 2026-08-12
- 신뢰도: 높음 (공식 개발자 changelog, 1차 출처)
- 왜 중요한가: PKM 도구가 노트 저장을 넘어 "에이전트를 초대해 도구를 만들게 하고, 그 사용량·권한을 관리자가 통제한다"는 계층까지 확장되는 사례입니다. [[secbrain-site]]가 GitHub 이슈 → Actions로 에이전트를 트리거하는 것과 같은 문제(누가 무엇을 실행하고 얼마나 쓰는지)를 상용 PKM이 어떻게 풀고 있는지 참고가 됩니다.
