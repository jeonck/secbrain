## 오늘 하나만 본다면

Claude Code v2.1.229(2026-08-12)가 "워크플로 팬아웃에서 같은 프리픽스를 쓰는 형제 에이전트들의 실행 순서를 살짝 어긋나게(stagger) 만들어, 뒤에 뜨는 에이전트가 캐시된 프롬프트 프리픽스를 그대로 읽고 다시 비용을 지불하지 않게" 바꿨습니다(`CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS=0`으로 끌 수 있음). 같은 릴리스 창(v2.1.224, 2026-08-07)에서는 세션당 200개였던 서브에이전트 스폰 상한도 완전히 없앴습니다(동시성·깊이 제한은 유지). 두 변경 모두 "여러 에이전트를 동시에 띄우는 워크플로"를 인프라 레벨에서 더 싸고 덜 제약적으로 만드는 방향이라, [[cog-architecture]]가 다루는 리드-워커 패턴을 이 저장소가 Workflow 도구로 실제 실행할 때 체감할 만한 변화입니다.

## agents

### Claude Code 워크플로 팬아웃 — 형제 에이전트 프롬프트 프리픽스 캐싱 (v2.1.229)
같은 접두사(prefix)를 공유하는 워크플로 형제 에이전트들의 시작 시점을 의도적으로 살짝 어긋나게 만들어, 나중에 시작하는 에이전트가 캐시된 프롬프트 프리픽스를 그대로 읽도록 바꿨습니다. 이전에는 동시에 시작하는 형제 에이전트들이 같은 프리픽스를 각자 다시 지불했습니다.

- 출처: [anthropics/claude-code CHANGELOG.md](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md) (v2.1.229, 2026-08-12) · 2026-08-12
- 신뢰도: 높음 (공식 리포지토리 CHANGELOG, 1차 출처)
- 왜 중요한가: 이 브리프 자체가 WebSearch/WebFetch를 반복 호출하는 세션에서 만들어지고, [[secbrain-site]]의 다른 스킬(weekly-review 등)도 병렬 에이전트를 띄울 여지가 있습니다. 프리픽스 캐싱이 자동으로 적용된다면 별도 설정 없이 팬아웃 비용이 줄어드는 셈입니다.

### 세션당 서브에이전트 스폰 상한(200개) 제거 (v2.1.224)
"200-subagent-per-session spawn cap"을 없애, 오래 도는 세션이 새 에이전트 생성을 거부당하지 않게 했습니다. 동시성·깊이 제한(기본 동시 20개, 중첩 깊이 3)은 그대로 유지됩니다.

- 출처: [anthropics/claude-code CHANGELOG.md](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md) (v2.1.224, 2026-08-07) · 2026-08-07
- 신뢰도: 높음 (공식 리포지토리 CHANGELOG, 1차 출처)
- 왜 중요한가: 총량 상한이 아니라 동시성·깊이만으로 제어하는 방향은, 장기 실행 워크플로를 설계할 때 "몇 개까지 띄울 수 있는가"보다 "한 번에 몇 개가 동시에 도는가"를 신경 써야 한다는 뜻입니다.

## devtools

### GitHub Copilot CLI v1.0.79 — kimi-k3 모델 지원, 샌드박스 인증 경로 정리
Copilot CLI가 오픈웨이트 모델 kimi-k3를 모델 선택지에 추가했고, 모델 선택 UI가 Recent/Recommended/New로 그룹화됩니다. 샌드박스 설정 키가 `sandbox.gitAuth`/`sandbox.ghAuth`에서 `sandbox.auth.git`/`sandbox.auth.gh`로 옮겨졌고, macOS에서 읽기 전용 경로가 쓰기 가능 경로 안에 있을 때 쓰기 권한이 잘못 상속되던 문제와 UNIX 도메인 소켓 미지원 문제를 고쳤습니다. Azure DevOps·GitLab 같은 비GitHub 원격 저장소 인증도 지원합니다.

- 출처: [github/copilot-cli releases — v1.0.79](https://github.com/github/copilot-cli/releases) · 2026-08-10
- 신뢰도: 높음 (공식 GitHub 릴리스 페이지)
- 왜 중요한가: Claude·OpenAI 계열 프론티어 모델 CLI에 오픈웨이트 모델(kimi-k3)이 선택지로 들어가는 사례로, [[2026-08-11-brief]]에서 다룬 Warp Agent CLI의 "프론티어+오픈웨이트 동시 제공" 흐름이 GitHub Copilot CLI에서도 반복되고 있습니다.

## pkm

### Notion MCP 뷰 도구 — 필터 종류 확장
`notion-create-view`/`notion-update-view` MCP 도구가 지원하는 필터 종류가 relation, person, status, created by, last edited by, unique ID, last visited, verification, place까지 늘었고, verification 필터가 뷰 응답에도 왕복 반영됩니다.

- 출처: [Notion Developer Changelog](https://developers.notion.com/page/changelog) · 2026-08-13
- 신뢰도: 높음 (공식 개발자 changelog, 1차 출처)
- 왜 중요한가: [[2026-08-12-brief]]에서 다룬 Notion Admin API의 에이전트 관리 확장에 이어, 이번엔 MCP를 통해 에이전트가 Notion 데이터베이스 뷰를 얼마나 세밀하게 조작할 수 있는지가 넓어진 사례입니다. relation·person 값은 이름이 아니라 페이지 URL/ID·사용자 ID로만 지정해야 하는 제약은, MCP 도구를 설계할 때 "사람이 읽는 이름"과 "기계가 참조하는 ID"를 분리해야 한다는 참고 사례로 볼 만합니다.
