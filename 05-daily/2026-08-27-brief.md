## 오늘 하나만 본다면

Heptabase가 2026-08-24 v1.105.0에서 CLI 0.6.0과 MCP 지원을 크게 넓혔습니다. 화이트보드의 계층·레이아웃·객체·연결·마인드맵을 CLI로 읽고 고칠 수 있고, MCP로는 카드·저널·이미지·PDF 페이지·화이트보드·태그 데이터베이스를 검색·생성·수정할 수 있습니다. PKM 툴이 "사람이 클릭하는 앱"에서 "에이전트가 직접 쓰는 파일 표면"으로 넘어가는 흐름이고, [[cog-architecture]]가 정리한 "자연어 in, `.md` out" 구조와 정확히 같은 방향입니다 — 다만 이 vault는 이미 마크다운이 원본이라 그 다리를 놓을 필요가 없다는 차이가 있습니다.

## pkm

### Heptabase v1.105.0 — CLI와 MCP로 화이트보드를 에이전트에 개방
2026-08-24 릴리스에서 Heptabase CLI가 0.6.0으로 올라가며 화이트보드의 계층·레이아웃·객체·섹션·연결·마인드맵을 읽고 수정하고 스크린샷으로 내보낼 수 있게 됐습니다. MCP 쪽도 카드·저널·이미지·PDF 페이지·화이트보드·마인드맵·태그 데이터베이스 검색에 더해 노트·저널·카드 속성·화이트보드 객체 배치까지 생성·수정 범위가 넓어졌습니다. 마인드맵에서 브랜치를 카드로 분리하기, 에디터 블록 멘션·임베드 등 UI 개선도 함께 나왔습니다.

- 출처: [Heptabase Changelog — v1.105.0](https://wiki.heptabase.com/changelog) · 2026-08-24
- 신뢰도: 높음 (공식 체인지로그, 1차 출처)
- 왜 중요한가: 카드·화이트보드 기반 PKM이 에이전트가 프로그래밍 방식으로 조작 가능한 표면을 갖췄다는 신호입니다. [[secbrain-site]]는 이미 마크다운 자체가 저장 포맷이라 "MCP로 노트에 접근" 문제가 처음부터 없었는데, 그 대비가 COG 구조를 데이터베이스 없이 가는 선택의 실익을 다시 보여줍니다.

## agents

### 구글 클라우드, AI 인프라 리포트 — 보안·거버넌스가 확장의 최대 장벽
2026-08-24 공개된 "State of AI Infrastructure" 리포트에서 기술 리더 79%가 보안·거버넌스·운영을 추론 확장의 가장 큰 난관으로 꼽았습니다. 에이전트가 이메일을 읽고 DB를 조회하고 API를 직접 호출하면서 툴 포이즈닝·간접 프롬프트 인젝션·동적 권한 관리가 새 위협 모델로 떠올랐고, 리포트는 ①시큐어-바이-디폴트 설계, ②목적에 맞춘 권한·신원 관리, ③중요 작업에 대한 사람 승인 플래깅 세 축을 권고합니다. 보안 리더들의 초점이 "침해 방지"에서 "출처(provenance) 검증"으로 옮겨가고 있다는 점도 짚었습니다.

- 출처: [State of AI infrastructure report: agent governance and security — Google Cloud Blog](https://cloud.google.com/blog/topics/ai-infrastructure/state-of-ai-infrastructure-report-agent-governance-and-security) · 2026-08-24
- 신뢰도: 높음 (기업 공식 블로그, 서베이 기반 1차 발표)
- 왜 중요한가: [[secbrain-site]]는 이슈 생성 → Actions 시크릿 → Claude Code 실행이라는 위임 체인이고, [[cog-architecture]]의 "리드가 판단, 워커가 파일 작업"도 같은 위임 문제입니다. 리포트가 꼽은 "중요 작업엔 사람 승인" 원칙은 이 저장소가 "소유자가 연 이슈만 실행"으로 이미 일부 구현한 것과 같은 방향이라, 다음에 권한 범위를 넓힐 때 참고할 만합니다.

## anthropic

### Claude Code 2.1.246 — /cd 즉시 반영, 서브에이전트 부분 출력 마킹
2026-08-25 배포된 2.1.246은 `/permissions`에 Auto mode 규칙을 보고 고치는 탭을 추가했고, `/cd`로 디렉토리를 옮기면 새 프로젝트 설정·훅·`.mcp.json`·스킬·에이전트가 `--resume` 없이 바로 적용되도록 바꿨습니다. 서브에이전트가 `maxTurns` 한도에서 멈추면 "완료"가 아니라 "부분 출력"으로 표시하고 `SendMessage`로 이어가라는 힌트를 주며, 헤드리스/SDK/클라우드 세션은 서버 오류나 연결 끊김으로 중간에 끊긴 응답을 자동으로 이어받습니다.

- 출처: [Claude Code changelog](https://code.claude.com/docs/en/changelog) · 2026-08-25
- 신뢰도: 높음 (공식 체인지로그, 1차 출처)
- 왜 중요한가: [[secbrain-site]]의 daily-brief·weekly-review는 정확히 비대화형(cloud/headless) 세션으로 예약 실행되므로, 서버 오류 시 자동 이어받기와 서브에이전트 부분 출력 마킹은 이 파이프라인이 조용히 실패하던 지점을 줄여줍니다.
