## 오늘 하나만 본다면

Claude Code 2.1.248(2026-08-27)이 `--restricted` 플래그(`CLAUDE_CODE_RESTRICTED=1`)를 추가했습니다. 명령 실행형 내장 도구와 `WebFetch`를 제거하고(`--tools`에 명시하지 않는 한), 파일 도구는 작업 디렉터리 안으로 제한하고, `bypassPermissions`를 거부하고, 사용자·프로젝트·로컬 설정 파일을 무시합니다. 같은 릴리스에서 `SendMessage`/`ListAgents` 크로스 세션 메시징이 Bedrock·Vertex·Foundry로 확장됐습니다. 이 저장소([[secbrain-site]])는 이슈로 트리거되는 예약 실행 파이프라인이라 "신뢰할 수 없는 입력(이슈 본문)으로 도구 접근이 있는 에이전트를 돌린다"는 정확히 그 위협 모델 안에 있고, `--restricted`는 [[cog-architecture]]가 말하는 "리드는 판단, 워커는 파일 작업"의 워커 쪽에 강제 경계를 씌울 수 있는 옵션입니다.

## anthropic

### Claude Code 2.1.248 — --restricted 플래그, 크로스 세션 메시징 확장
2026-08-27 배포. `--restricted`는 명령/코드 실행 도구와 `WebFetch`를 제거하고 파일 도구를 작업 디렉터리 안으로 묶으며 `bypassPermissions`를 거부하고 설정 파일 로드를 무시하는 잠금 모드입니다. 에이전트 프런트매터에 `experimental.cacheTtl`로 개별 프롬프트 캐시 TTL을 지정할 수 있게 됐고, `SendMessage`/`ListAgents` 같은 머신 내 세션 간 메시징이 Bedrock·Vertex·Foundry에서도 동작합니다. 이 외 다수의 버그 수정(OAuth 갱신 후 캐시 미스, 워크트리 잠금, 훅 오류 처리 등)이 포함됐습니다.

- 출처: [Claude Code changelog](https://code.claude.com/docs/en/changelog) · 2026-08-27
- 신뢰도: 높음 (공식 체인지로그, 1차 출처)
- 왜 중요한가: [[secbrain-site]]는 GitHub Actions가 이슈를 열면 Claude Code를 실행하는 구조입니다. `--restricted`를 데일리브리프·위클리리뷰처럼 "vault 안에서만 쓰고 명령 실행이 필요 없는" 스킬에 적용하면, 이슈 본문에 담긴 프롬프트 인젝션이 임의 명령 실행으로 번질 표면을 아예 없앨 수 있습니다.

## agents

### AccuKnox AgentZ — eBPF 커널 강제로 에이전트별 권한을 스코프
2026-08-27 출시. AgentZ는 컨테이너가 아니라 에이전트 아이덴티티를 대상으로 KubeArmor/eBPF 런타임을 적용하는 제로트러스트 샌드박스로, 네트워크·프로세스·파일·패키지·MCP/툴 접근을 6개의 독립된 커널 강제 컨트롤로 제한합니다. 에이전트마다 아이덴티티·허용 패키지·허용 호스트·툴별 권한이 서명된 객체 하나로 묶이고, 시크릿은 볼트에 남아 에이전트는 키를 보지 않고 스코프된 접근만 받습니다. OpenAI·Claude·Grok 등 모델 애그노스틱을 표방합니다.

- 출처: [AccuKnox Launches AgentZ — GlobeNewswire](https://www.globenewswire.com/news-release/2026/08/27/3351759/0/en/accuknox-launches-agentz-to-help-enterprises-build-run-and-govern-ai-agents-at-scale.html) · 2026-08-27
- 신뢰도: 중간 (기업 보도자료 1차 발표지만 제품 마케팅 성격이 강해 독립 검증 없음)
- 왜 중요한가: 어제 브리프의 구글 클라우드 리포트가 짚은 "에이전트 보안·거버넌스가 최대 확장 장벽"이라는 문제에 대한 구체적 제품 답 중 하나입니다. Claude Code의 `--restricted`(anthropic 항목)와 접근 방식이 다른데, 하나는 CLI 플래그로 도구를 아예 빼는 방식이고 다른 하나는 런타임 커널 레벨에서 스코프하는 방식이라 비교해볼 만합니다.

### GitHub Copilot CLI 1.0.81 — 플러그인 대시보드 정식 공개
2026-08-27 릴리스. `/plugin`, `/mcp`, `/skills`를 한 대시보드로 묶은 플러그인 대시보드가 전체 사용자에게 열렸고(`PLUGINS_DASHBOARD=false`로 끌 수 있음), Gemini 3.7 Flash 지원과 `/sandbox`에서 Ctrl+E로 `settings.json`을 에디터로 열기, `--usage-output-file` JSON에 에이전트별 사용량 지표가 추가됐습니다. `copilot --continue`가 저장된 브랜치·git 컨텍스트를 다시 불러오도록 개선됐습니다.

- 출처: [github/copilot-cli releases — v1.0.81](https://github.com/github/copilot-cli/releases) · 2026-08-27
- 신뢰도: 높음 (공식 GitHub 릴리스 노트, 1차 출처)
- 왜 중요한가: 어제 브리프의 GitHub Copilot Customize 탭(발견 가능성)에 이어, 플러그인·MCP·스킬을 한 곳에서 관리하는 흐름이 CLI까지 내려온 사례입니다. 이 vault가 `.claude/skills/`를 마크다운으로 노출하는 방식과 다른 층위에서 같은 문제(에이전트 확장 기능을 어떻게 찾고 켜게 할까)를 풉니다.
