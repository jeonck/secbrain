## 오늘 하나만 본다면

Anthropic이 2026-09-01 Enterprise Frontier Safeguards(EFS)를 발표했습니다. 영 데이터 보유(ZDR)의 프라이버시와 오용 탐지 기능을 결합하되, 모니터링 데이터의 커스터디·키·인간 검토는 Anthropic이 아닌 고객이 통제하는 클라우드 인프라에 둡니다. 100개 이상 기업(금융·의료·법률 등 규제 산업)과 공동 개발했고, Claude Code·Claude Enterprise·AWS Bedrock·Google Agent Platform·Microsoft Foundry에 단계적으로 적용됩니다. [[secbrain-site]]가 GitHub Actions 러너에서 시크릿을 쥐고 Claude Code를 실행하는 구조라, "탐지 로직은 벤더가 갖되 데이터 커스터디는 고객이 갖는" 이 분리 패턴은 이 파이프라인의 권한 설계에도 참고가 됩니다.

## anthropic

### Enterprise Frontier Safeguards(EFS) 발표 — 오용 탐지 로그를 고객 클라우드에
Anthropic 공식 발표(2026-09-01). 데이터 보유 정책에 대한 규제 산업 고객들의 반발 이후 나온 대안으로, ZDR의 프라이버시를 유지하면서도 세션 간 오용 탐지는 계속 수행합니다. 핵심은 "탐지는 Anthropic이 하되, 로그의 커스터디·암호화 키·인간 검토 권한은 고객이 쥔다"는 분리 구조입니다. 2026년 가을부터 단계적으로 무상 제공될 예정입니다.

- 출처: [Developing Enterprise Frontier Safeguards with our customers — Anthropic 공식](https://www.anthropic.com/news/enterprise-frontier-safeguards) · 2026-09-01
- 신뢰도: 높음 (1차 출처, 공식 발표)
- 왜 중요한가: [[secbrain-site]]는 Claude Code가 vault 데이터에 직접 접근해 커밋까지 하는 구조라, "에이전트의 행동 로그는 누가 갖고 누가 보는가"라는 질문이 [[에이전트-권한-경계-체크리스트]]와 정확히 겹칩니다. 벤더가 커스터디를 고객에게 넘기는 이번 설계는 그 체크리스트에 추가할 만한 참고 사례입니다.

## agents

### NIST, "에이전트 AI에는 강력한 신원 기반이 필요하다" — 자격증명 공유·장기 토큰을 위험 요소로 지목
NIST 사이버보안 인사이트 블로그 공식 글(2026-08-27). 에이전트가 사람보다 훨씬 빠르고 큰 규모로 동작하기 때문에 기존 IAM(신원·접근권한 관리)의 약점이 증폭된다고 지적합니다. 위험 요소로 ①자격증명 공유 ②장기 정적 토큰(API 키) ③과도한 접근권한 ④로컬 사용자 계정으로 에이전트 실행 ⑤승인 피로로 인한 과도한 인간 개입 5가지를 꼽고, 새 기술이 아니라 OAuth 2.0·SPIFFE 같은 기존 IAM 표준을 에이전트에도 그대로 적용하라고 권고합니다.

- 출처: [Back to the Future: Why Agentic AI Needs a Strong Identity Foundation — NIST 공식 블로그](https://www.nist.gov/blogs/cybersecurity-insights/back-future-why-agentic-ai-needs-strong-identity-foundation) · 2026-08-27
- 신뢰도: 높음 (1차 출처, 미국 표준기술연구소 공식 블로그)
- 참고: 발행일이 7일 창(2026-08-28~09-04) 하루 밖입니다 — 구자료로 표시.
- 왜 중요한가: NIST가 나열한 "장기 정적 토큰"·"로컬 계정으로 에이전트 실행" 위험은 GitHub Actions에서 `GITHUB_TOKEN`으로 Claude Code를 실행하는 [[secbrain-site]] 구조와 직접 관련이 있습니다. [[에이전트-권한-경계-체크리스트]]에 "토큰 수명"과 "신원 위임" 항목으로 반영할 만합니다.

## devtools

### GitHub Actions, 워크플로우 전용 최소 권한 항목 `vulnerability-alerts` 추가
GitHub 공식 체인지로그(2026-09-03). `GITHUB_TOKEN`에 Dependabot 알림 읽기 전용 접근을 부여하는 `vulnerability-alerts` 권한(`read`/`none`)이 새로 생겨, 기존의 더 넓은 스코프 대신 최소 권한으로 알림만 읽을 수 있습니다. 같은 업데이트에서 러너 버전 지원 종료 시점을 조회하는 REST API와, 재사용 가능한 워크플로우가 자신의 출처(`workflow_ref`, `workflow_sha` 등)를 런타임에 식별할 수 있는 job 컨텍스트 속성도 추가됐습니다.

- 출처: [GitHub Actions: Early September 2026 updates — GitHub 공식 체인지로그](https://github.blog/changelog/2026-09-03-github-actions-early-september-2026-updates/) · 2026-09-03
- 신뢰도: 높음 (1차 출처, 공식 체인지로그)
- 왜 중요한가: [[secbrain-site]]가 매 push마다 GitHub Actions로 빌드·실행되는 구조라, `GITHUB_TOKEN` 권한을 최소화하는 옵션이 늘어난 것은 워크플로우 파일의 `permissions` 블록을 다시 점검할 근거가 됩니다.
