## 오늘 하나만 본다면

Anthropic이 커머스 에이전트 구축 가이드에서 "여러 서브에이전트로 쪼개지 말고 스킬을 얹은 단일 에이전트 루프를 쓰라"고 권장했습니다. 자주 쓰는 내용은 시스템 프롬프트에, 가끔 쓰는 능력은 스킬로 분리하라는 원칙인데, 이건 `.claude/skills/`에 `daily-brief`·`braindump`·`ask` 등을 마크다운 지시문으로 얹어둔 [[secbrain-site]]의 구조와 정확히 같은 패턴입니다. 이 저장소의 설계가 Anthropic이 커머스처럼 무관해 보이는 도메인에서 독립적으로 도달한 결론과 일치한다는 확인 정도로 읽으면 됩니다.

## agents

### Anthropic 커머스 에이전트 아키텍처 가이드 — "서브에이전트 대신 스킬"
Anthropic이 소매·여행·엔터테인먼트·통신 분야 프로덕션 에이전트를 겨냥한 아키텍처 가이드를 냈습니다. 핵심 권고는 (1) 여러 서브에이전트로 쪼개는 대신 스킬을 붙인 단일 에이전트 루프를 쓸 것 — 핸드오프마다 컨텍스트가 유실되고 지연이 늘기 때문, (2) 트래픽의 1/3 이상에 쓰이는 내용만 시스템 프롬프트에 두고 나머지는 스킬로 뺄 것, (3) "모델의 툴 호출이 직접 돈을 움직이거나 비즈니스 상태를 바꾸지 않는다" — 안전장치는 프롬프트가 아니라 코드(하네스)에 둘 것.

- 출처: [The anatomy of effective commerce agents — Anthropic 공식 블로그](https://claude.com/blog/the-anatomy-of-effective-commerce-agents) · 2026-09-02
- 신뢰도: 높음 (1차 출처, 공식 블로그)
- 왜 중요한가: [[secbrain-site]]의 스킬 구조(마크다운 지시문 + 스킬별 SKILL.md)가 바로 이 "단일 에이전트 + 스킬" 패턴입니다. 안전장치를 코드에 두라는 권고는 [[에이전트-권한-경계-체크리스트]]가 다루는 "저장소 소유자가 연 이슈만 실행" 같은 하네스 레벨 경계와 같은 방향입니다.

### Claude Code — 게이트웨이 회귀 버그, 하루 만에 수정 (2.1.266 → 2.1.267)
2026-09-08 배포된 2.1.266에서 문서화되지 않은 `CLAUDE_CODE_USE_GATEWAY` 환경변수가 `ANTHROPIC_BASE_URL`·인증 토큰 설정 여부와 무관하게 게이트웨이 로그인을 강제하는 회귀가 발생해 프록시 구성이 깨졌습니다. 2026-09-09 배포된 2.1.267에서 이를 수정했고, 같은 릴리스에 모든 프로바이더(Bedrock·Vertex·Foundry 포함)의 이펙트 레벨 상한을 지정하는 `maxEffortLevel` 설정도 추가됐습니다.

- 출처: [Claude Code Changelog — 공식 문서](https://code.claude.com/docs/en/changelog) · 확인일 2026-09-09
- 신뢰도: 높음 (1차 출처, 공식 체인지로그)
- 왜 중요한가: [[secbrain-site]]는 GitHub Actions가 매일 Claude Code로 스킬을 실행하는 구조입니다. 이 저장소는 게이트웨이/프록시를 쓰지 않아 이번 회귀의 직접 영향은 없었지만, 릴리스 주기가 1~2일 단위로 빠르다는 점은 예약 실행 안정성을 볼 때 계속 체크할 만합니다.

## devtools

### GitHub Copilot CLI v1.0.83 — Claude Fable 5.1 지원, MCP OAuth 표준화
2026-09-04 배포. `model:` 필드에 여러 모델을 순서대로 지정해 가용한 첫 모델을 쓰는 폴백 목록과 `model-policy: required`(해당 목록으로만 모델 전환 고정) 기능이 추가됐고, Claude Fable 5.1을 모델 목록에 지원합니다. MCP OAuth 로그인에 CIMD(Client ID Metadata Document) 방식을 지원하며, `/sandbox` 정책이 경로 권한을 출처별로 묶어 보여주도록 개선됐습니다.

- 출처: [copilot-cli changelog.md — GitHub 공식 저장소](https://github.com/github/copilot-cli/blob/main/changelog.md) · 2026-09-04
- 신뢰도: 높음 (1차 출처, 공식 체인지로그)
- 왜 중요한가: CIMD 기반 MCP OAuth와 모델 폴백 목록은 [[에이전트-권한-경계-체크리스트]]가 다루는 "어떤 자격 증명으로 어떤 툴에 접근하는가" 질문과 맞닿아 있어, Claude Code 쪽 MCP 인증 방식과 비교해볼 거리입니다.

### Notion 검색 API — 키워드 검색과 AI 검색 분리
2026-09-02, Notion이 MCP/API의 `notion-search`를 키워드 전용(정확한 텍스트·사용자 조회, Slack·Drive 등 연결 앱은 더 이상 검색하지 않음)으로 좁히고, 연결된 워크스페이스 전체를 자연어로 훑는 시맨틱 검색을 새 `notion-ai-search` 툴로 분리했습니다. 이어 2026-09-09에는 플랜별 요청 한도(비즈니스/엔터프라이즈 분당 600건, 그 외 분당 180건)와 재시도 속도 개선이 나왔습니다.

- 출처: [Notion Developers Changelog — 공식 문서](https://developers.notion.com/page/changelog) · 2026-09-02, 2026-09-09
- 신뢰도: 높음 (1차 출처, 공식 체인지로그)
- 왜 중요한가: 이 vault는 파일 기반 PKM이라 직접 영향은 없지만, "정확한 검색"과 "의미 기반 검색"을 툴 단위로 분리한 결정은 [[interests]]의 `pkm` 키가 계속 추적할 만한 설계 이슈입니다 — secbrain 사이트 검색도 결국 같은 트레이드오프를 마주하게 됩니다.
