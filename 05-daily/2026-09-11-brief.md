## 오늘 하나만 본다면

GitHub Actions가 워크플로·잡 단위로 캐시 접근을 `read`/`write`/`write-only`/`none`으로 세분화하는 `cache-mode`를 정식 출시했습니다. `secbrain-site`의 `pages.yml`이 실제로 캐시를 쓰는 워크플로라, 어제 브리프의 `vulnerability-alerts` 최소 권한 논의에 이어 바로 적용해볼 수 있는 구체적인 대상입니다.

## devtools

### GitHub Actions — cache-mode로 캐시 접근 최소 권한화
`read`(복원만), `write`(복원+저장), `write-only`(저장만), `none`(차단) 네 단계로 캐시 접근을 워크플로·잡 레벨에서 지정할 수 있습니다. 잡 설정이 워크플로 설정을 덮어쓰고, 재사용 워크플로는 호출자가 허용한 것보다 더 넓은 접근을 가질 수 없으며, `pull_request_target`처럼 신뢰도가 낮은 이벤트에 `write`/`write-only`를 쓰면 경고가 뜹니다. 캐시 포이즈닝 방지가 목적이며 모든 플랜에 GA로 적용됐습니다.

- 출처: [Control GitHub Actions cache access with cache-mode — GitHub Changelog 공식](https://github.blog/changelog/2026-09-10-control-github-actions-cache-access-with-cache-mode/) · 2026-09-10
- 신뢰도: 높음 (1차 출처, 공식 체인지로그)
- 왜 중요한가: [[secbrain-site]]의 `pages.yml`이 빌드 캐시를 씁니다. [[에이전트-권한-경계-체크리스트]]가 다루는 "필요한 만큼만 권한을 준다" 원칙을 캐시 접근에도 적용할 수 있는 기능이 생긴 것이라, `write-only`나 `none`으로 좁힐 여지가 있는지 점검해볼 만합니다.

### GitHub Copilot — 에이전트 작업에 대한 엔터프라이즈 관리형 권한
관리자가 Copilot 에이전트의 셸 명령·파일 읽기/쓰기·네트워크 도메인 접근을 "차단/승인 필요/무제한" 세 범주로 조직 전체에 중앙 통제할 수 있게 됐습니다. 이 제한은 사용자·워크스페이스 설정이나 자동 승인, 기존에 저장된 승인으로도 약화시킬 수 없다고 명시돼 있습니다. Copilot 앱·CLI·VS Code(Agent Host) 세션에 적용됩니다.

- 출처: [Enterprise-managed permissions for GitHub Copilot agent operations — GitHub Changelog 공식](https://github.blog/changelog/2026-09-09-enterprise-managed-permissions-for-github-copilot-agent-operations/) · 2026-09-09
- 신뢰도: 높음 (1차 출처, 공식 체인지로그)
- 왜 중요한가: "사용자 설정으로도 약화 불가"라는 조직 레벨 강제 방식은 [[에이전트-권한-경계-체크리스트]]가 아직 다루지 않는 층위(개인 설정 vs 조직 정책)라, 체크리스트를 보강할 때 참고할 만한 설계입니다.

## anthropic

### Claude Code 2.1.269 — 프롬프트 캐시 무효화 수정, Workflow 동시 에이전트 상한 상향
출력 토큰 한도로 잘린 응답이 자동 재개될 때 프롬프트 캐시가 부분적으로 무효화되던 문제와, 세션을 중단 후 재개하면 이전 컨텍스트 재전송 방식이 바뀌어 캐시 재사용률이 떨어지던 문제를 수정했습니다. `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`로 Workflow 도구의 동시 에이전트 상한을 1~256 범위에서 올릴 수 있게 됐고, `claude plugin eval`로 플러그인 eval 스위트를 재현 가능한 JSON/HTML 리포트로 실행하는 기능도 추가됐습니다.

- 출처: [Claude Code Changelog — 공식 문서](https://code.claude.com/docs/en/changelog) · 2026-09-11
- 신뢰도: 높음 (1차 출처, 공식 체인지로그)
- 왜 중요한가: 이 브리프를 포함해 이 vault의 예약 실행 자체가 Claude Code로 돌아갑니다. 프롬프트 캐시 무효화 수정은 매일 반복 실행되는 스킬들의 비용·속도에 직접 영향을 줍니다.

## agents

### OpenAI Agents API — Codex 하니스를 퍼블릭 베타로 공개
OpenAI가 Codex를 구동하는 에이전트 하니스를 API로 열었습니다. 세션·오케스트레이션·컨텍스트 압축을 OpenAI가 관리하고, 개발자는 도구와 실행 환경(OpenAI 호스팅 샌드박스 또는 E2B·Modal·Vercel 등 서드파티)만 고르면 됩니다. 멀티 에이전트 기능은 메인 에이전트가 독립된 컨텍스트를 가진 서브에이전트에 작업을 위임하고 결과를 취합하는 구조이며(`max_concurrent_subagents`로 동시 개수 설정), 토큰·도구 사용량 외 추가 요금은 없습니다.

- 출처: [Introducing the Agents API and hosted sandboxes — OpenAI Developer Community 공식 공지](https://community.openai.com/t/introducing-the-agents-api-and-hosted-sandboxes/1396481) · 2026-09-10
- 신뢰도: 높음 (1차 출처, 공식 발표 채널)
- 왜 중요한가: "메인 에이전트가 서브에이전트에 위임"하는 구조는 이 vault가 스킬 기반 단일 루프로 예약 실행을 짜는 방식과 대비됩니다. 같은 문제에 대한 또 다른 답이 하나 늘었으니, [[secbrain-site]]의 실행 구조를 재검토할 때 비교 대상으로 남겨둘 만합니다.
