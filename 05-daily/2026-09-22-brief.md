## 오늘 하나만 본다면

Anthropic이 Claude Opus 5.5(`claude-opus-5-5`)를 공개했습니다 — 컨텍스트 100만 토큰, 상시 켜진 적응형 사고, 가격은 Opus 5 대비 입출력 모두 20% 인하($4/$20 per MTok)입니다. 같은 날 Claude Code 2.1.280은 Pro·Team Standard 플랜의 기본 모델을 Sonnet에서 Opus로 바꿨습니다. secbrain의 예약 파이프라인(daily-brief·weekly-review 등)이 바로 이 Claude Code 위에서 돌기 때문에, 플랜에 따라 오늘부터 실제로 실행되는 모델이 바뀌었을 수 있는 변경입니다.

## anthropic

### Claude Opus 5.5 출시 — 컨텍스트 100만, 사고 상시 활성화, 가격 20% 인하
장시간 에이전트 코딩·지식 작업에 맞춘 모델로, 기본 컨텍스트 100만 토큰에 최대 출력 12.8만 토큰입니다. `thinking: {"type": "disabled"}`가 400 오류를 내는 등 사고를 끌 수 없고 `effort` 파라미터로만 깊이를 조절합니다. `tool_choice`의 `any`/`tool` 타입도 더 이상 지원하지 않아 `auto` + strict tool use로 대체해야 합니다.

- 출처: [Claude Platform Release Notes — 공식 문서](https://platform.claude.com/docs/en/release-notes/overview) · 2026-09-22
- 신뢰도: 높음 (1차 출처, 공식 릴리스 노트)
- 왜 중요한가: `computer_20251124` 같은 기존 툴셋이 Claude API·Google Cloud에서 400을 내는 breaking change라, secbrain 파이프라인이 이 모델로 넘어갈 경우 스킬 내 도구 호출 방식을 다시 점검할 필요가 있습니다.

### Claude Code 2.1.280 — Opus 5.5 반영, Pro·Team Standard 기본 모델 Sonnet→Opus
Opus 5.5 지원과 함께 Pro·Team Standard 플랜의 기본 모델이 Opus로 바뀌었고, `/skills`·`/plugin` 목록에 마우스 스크롤 지원, MCP 툴 설명 길이를 조절하는 `CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH` 환경변수 등 60건 이상의 수정이 함께 들어갔습니다.

- 출처: [Claude Code Changelog — 공식 문서](https://code.claude.com/docs/en/changelog) · 2026-09-22
- 신뢰도: 높음 (1차 출처, 공식 체인지로그)
- 왜 중요한가: [[cog-architecture]]의 "리드(비싼 모델)가 판단, 워커(싼 모델)가 I/O" 비용 패턴이 전제로 삼던 기본 모델 자체가 바뀐 것이라, [[2026-08-10-에이전트-비용-구조-정리와-빈틈]]에서 정리한 비용 구조를 다시 볼 계기입니다.

## agents

### DolphinBench — 에이전트 메모리를 정확도·비용·지연 세 축으로 동시에 재는 벤치마크
기존 메모리 벤치마크가 대화형 QA 위주였던 것과 달리, DolphinBench는 지식노동 페르소나 3종에 걸쳐 페르소나당 약 50만 토큰 분량의 사용자 메시지와 200개 검증 과제를 두고 "과거 맥락이 있을 때만 성공, 없을 때는 실패"하도록 과제 품질을 강제합니다. 저자들은 정확도·총비용·지연을 동시에 보고하는 벤치마크가 지금까지 없었다고 밝힙니다.

- 출처: [DolphinBench: Mapping the Pareto Frontier of Agent Memory — arXiv](https://arxiv.org/abs/2609.24971) · 2026-09-21
- 신뢰도: 높음 (1차 출처, arXiv 프리프린트 — 동료 심사는 아직 거치지 않음)
- 왜 중요한가: secbrain 자체가 "메모리 = `.md` 파일"이라는 [[cog-architecture]]의 전제 위에서 돌기 때문에, 정확도뿐 아니라 비용·지연까지 같이 재라는 이 벤치마크의 기준은 vault를 근거로 답을 조립하는 `ask`·`weekly-review` 같은 스킬을 평가할 때 참고할 축입니다.

## devtools

### GitHub Copilot에 Grok 4.7 모델 추가
xAI의 최신 추론 모델 Grok 4.7이 GitHub Copilot의 모델 선택지에 추가됩니다. 에이전트형 코딩과 복잡한 다단계 작업에 맞춰졌다고 소개되며, Pro·Pro+·Max·Business·Enterprise 등급에서 VS Code·Visual Studio·Copilot CLI·Copilot 앱·JetBrains·Xcode·Eclipse 모델 선택기에 순차 노출됩니다. 사용량 기반 과금에서는 제공사 정가로 청구됩니다.

- 출처: [Grok 4.7 is now available in GitHub Copilot — GitHub Changelog](https://github.blog/changelog/2026-09-21-grok-4-7-is-now-available-in-github-copilot/) · 2026-09-21
- 신뢰도: 높음 (1차 출처, 공식 GitHub 체인지로그)
- 왜 중요한가: 경쟁 코딩 도구가 복수 공급사 모델을 나란히 붙이는 방향으로 가는 사례로, 오늘 anthropic 항목의 Claude Code 기본 모델 전환과 마찬가지로 "비용·품질을 사용자가 어떻게 고르게 할 것인가" 문제의 또 다른 해법입니다.
