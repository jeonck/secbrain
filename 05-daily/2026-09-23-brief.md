## 오늘 하나만 본다면

Anthropic 공식 릴리스 노트(9/22)가 `inline-tools-2026-09-15` 베타 헤더로 켜는 "mid-conversation tools"를 문서화했습니다 — 대화 시작의 `tools` 배열을 건드리지 않고, 뒤에 붙는 `system` 메시지의 `tool_addition` 블록으로 도구를 통째로 추가·교체할 수 있어 프롬프트 캐시가 깨지지 않습니다. 이 브리프를 쓰는 이 세션이 오늘 정확히 이 패턴을 밟았습니다: `WebSearch`·`WebFetch`가 처음부터 로드돼 있지 않고, 필요해진 시점에 `ToolSearch`로 스키마를 가져와서야 호출 가능해졌습니다. 도구를 언제·왜 늦게 공개하는지가 이제 벤더 문서로도 뒷받침되는 설계 패턴이라는 뜻입니다.

## anthropic

### Mid-conversation tools 베타 — 프롬프트 캐시를 안 깨고 도구를 중간에 추가
`inline-tools-2026-09-15` 헤더를 켜면 `tools` 배열과 이전 메시지를 그대로 둔 채, 뒤에 붙는 `system` 메시지가 새 도구의 전체 정의를 `tool_addition` 블록으로 실어 나릅니다. 이전 방식(`mid-conversation-tool-changes-2026-07-01` 헤더)은 `tools` 배열 자체를 고쳐야 해서 대화 전체의 캐시가 깨졌던 것과 대비됩니다. MCP 커넥터 쪽도 `mcp-client-2026-09-15` 헤더로 도구 목록을 중간에 채워 넣을 수 있습니다.

- 출처: [Claude Platform Release Notes — 공식 문서](https://platform.claude.com/docs/en/release-notes/overview) · 2026-09-22
- 신뢰도: 높음 (1차 출처, 공식 릴리스 노트)
- 왜 중요한가: 위 "오늘 하나만 본다면"에서 쓴 대로, 이 secbrain 파이프라인이 도구를 다루는 방식과 같은 결의 패턴입니다. 도구 스키마를 처음부터 다 실어 캐시를 무겁게 할지, 늦게 불러와 컨텍스트를 아낄지의 트레이드오프를 다룰 때 참고할 1차 근거입니다.

### Claude Code v2.1.281 — 게이트웨이·Bedrock 권한 기능 대거 추가, 세션 재개·캐시 버그 다수 수정
오늘(9/23) 배포된 버전으로 Bedrock 업스트림에 `assume_role`·`guardrail` 설정, 게이트웨이 설정에 `telemetry.resource_attributes`가 추가됐고, 세션 재개·프롬프트 캐시·툴 콜 처리·샌드박스 권한 프롬프트 관련 버그가 다수 고쳐졌습니다.

- 출처: [Claude Code Changelog — 공식 문서](https://code.claude.com/docs/en/changelog) · 2026-09-23
- 신뢰도: 높음 (1차 출처, 공식 체인지로그)
- 왜 중요한가: 대부분 엔터프라이즈 게이트웨이·Bedrock 설정이라 이 vault와 직접 닿지는 않지만, 세션 재개·프롬프트 캐시 버그 수정은 daily-brief·weekly-review 같은 예약 실행(`claude -p`/Agent SDK 경로)의 안정성에 걸리는 부분입니다.

## agents

### Microsoft Agent Framework (Python) 1.19.0 — 벡터스토어 프로바이더 프로토콜, 오케스트레이션 워크플로 이름 고정
벡터스토어를 표준 인터페이스로 다루는 새 프로토콜과 MongoDB·Azure Cosmos DB NoSQL 커넥터(알파)가 추가됐고, 내장 오케스트레이션 워크플로에 안정적인 이름이 붙어 참조가 쉬워졌습니다.

- 출처: [python-1.19.0 — GitHub Releases](https://github.com/microsoft/agent-framework/releases/tag/python-1.19.0) · 2026-09-18
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스)
- 왜 중요한가: secbrain은 벡터스토어를 쓰지 않아 이 릴리스 자체와는 거리가 있지만, "오케스트레이션 워크플로에 이름을 고정한다"는 방향은 `ask`·`weekly-review`처럼 서로 다른 스킬이 vault를 근거로 결과를 조립하는 구조를 나중에 문서화할 때 참고할 만한 패턴입니다.

## devtools

### GitHub Copilot 앱 — 로컬 샌드박싱 퍼블릭 프리뷰
Copilot 앱이 파일시스템·네트워크·Git/GitHub CLI 자격증명 접근을 프로젝트 단위로 제한하는 로컬 샌드박스를 추가했습니다. 기본은 꺼짐이고 `/sandbox on`으로 세션별로 켤 수 있으며, OS가 요청한 제한을 강제할 수 없으면 샌드박스 세션 자체가 실패합니다(제한 없이 그냥 도는 대신).

- 출처: [Local sandboxing in the GitHub Copilot app — GitHub Changelog](https://github.blog/changelog/2026-09-23-local-sandboxing-in-the-github-copilot-app/) · 2026-09-23
- 신뢰도: 높음 (1차 출처, 공식 GitHub 체인지로그)
- 왜 중요한가: [[에이전트-권한-경계-체크리스트]]가 다루는 "사람이 매 실행을 검토하지 않는 예약 파이프라인" 문제 그 자체입니다. "제한을 강제 못 하면 실패시킨다"는 fail-closed 설계는 이 vault의 예약 실행 스킬(daily-brief 포함)에도 참고할 기준선입니다.

## pkm

### Notion "Skills" — 팀 전체가 공유하는 재사용 가능한 AI 지침 (구자료, 9/15)
Notion이 "AI가 우리 팀이 일하는 방식을 배우게 하는 재사용 가능한 지침"이라고 설명하는 Skills 기능을 출시했습니다. Custom Agents가 이 Skills를 불러 쓰고, 서브에이전트·툴 연결·모델 선택기도 같이 개편됐습니다. 7일 신선도 기준(9/16~)보다 하루 빠른 9/15 발표라 "구자료"로 표시합니다.

- 출처: [Notion Releases — 공식](https://www.notion.com/releases) · 2026-09-15
- 신뢰도: 높음 (1차 출처, 공식 릴리스 페이지)
- 왜 중요한가: `.claude/skills/`가 마크다운 지시문으로 이 vault의 동작 전부를 정의하는 구조와 이름·개념이 정확히 같은 방향입니다. Notion이 이걸 제품 표준 용어로 채택했다는 건, "스킬 = 재사용 가능한 AI 지침 파일"이라는 이 vault의 전제가 업계에서도 같은 이름으로 굳어지고 있다는 신호입니다.
