## 오늘 하나만 본다면

Claude Code v2.1.282가 오늘(9/24) 배포되면서 "sessions failing on every turn with an Invalid `data` in `redacted_thinking` block" 버그와 `--continue`/`--resume`가 이전 메시지를 변형된 형태로 재전송하던 문제가 고쳐졌습니다. 이 secbrain vault의 daily-brief·weekly-review는 정확히 이 세션 재개·재시도 경로(예약된 `claude -p`/Agent SDK 실행)에 얹혀 있으므로, 이런 수정은 사용해보기 전엔 몰랐던 형태로 예약 실행의 안정성에 직접 걸립니다.

## anthropic

### Claude Code v2.1.282 — 세션 재개·redacted_thinking 재시도 버그 수정, `/artifacts` 개선
오늘 배포된 버전으로 대화 기록에 API가 복호화할 수 없는 웹 검색 결과가 있을 때 모든 요청이 400 에러로 실패하던 문제, 재개된 세션이 이전 메시지를 바뀐 형태로 재전송하던 문제, `redacted_thinking` 블록 관련 API 에러로 매 턴 실패하던 문제(이제 thinking 블록을 지우고 한 번 재시도)가 고쳐졌습니다. `maxProseWidth` 설정과 `/artifacts` 목록 탐색(PgUp/PgDn, 마우스 휠) 개선도 추가됐습니다.

- 출처: [Claude Code Changelog — 공식 문서](https://code.claude.com/docs/en/changelog) · 2026-09-24
- 신뢰도: 높음 (1차 출처, 공식 체인지로그)
- 왜 중요한가: 위 "오늘 하나만 본다면" 참고. [[secbrain-site]]의 GitHub Actions 파이프라인이 세션 재개·리트라이 경로를 그대로 쓰는 예약 실행이라, 이런 버그 수정은 남의 일이 아닙니다.

### Claude Platform — Cache diagnostics 베타 졸업
`cache-diagnosis-2026-04-07` 베타 헤더 없이도 Messages 요청에 `diagnostics` 객체를 넣으면 캐시 진단 정보를 받을 수 있게 정식 기능이 됐습니다. 헤더를 계속 보내도 기존대로 동작합니다.

- 출처: [Claude Platform Release Notes — 공식 문서](https://platform.claude.com/docs/en/release-notes/overview) · 2026-09-23
- 신뢰도: 높음 (1차 출처, 공식 릴리스 노트)
- 왜 중요한가: 이 vault의 스킬들은 반복적으로 같은 시스템 프롬프트·CLAUDE.md를 캐시에 태우는 구조라, 캐시 적중률을 직접 확인할 수단이 정식 기능이 됐다는 건 [[cog-architecture]]가 말하는 "비용 패턴"을 실측할 수 있게 됐다는 뜻입니다.

## agents

### Claude Code Projects 재설계 — 코디네이터가 병렬 스레드를 조율
Anthropic이 Projects를 "폴더에서 대화로" 재설계했습니다. 하나의 프로젝트가 요청을 스코핑하고, 병렬 스레드(각각 자기 브랜치·리포 사본에서 도는 클라우드 세션)로 작업을 나누고, 결과를 리뷰·조립하는 코디네이터 구조입니다. 스레드들이 프로젝트 메모리를 공유해 여러 날에 걸친 작업에서 반복 설명이 줄어듭니다. 9/17 Pro·Max 클라우드 세션 사용자 대상 베타로 시작했습니다.

- 출처: [Projects redesigned: from folder to conversation — Claude 공식 블로그](https://claude.com/blog/projects-redesigned) · 2026-09-17
- 신뢰도: 높음 (1차 출처, 공식 제품 블로그)
- 왜 중요한가: [[cog-architecture]]가 정리한 "리드가 판단, 워커가 I/O" 패턴을 Anthropic이 제품으로 만든 형태입니다. 다만 사람이 매 턴 리뷰하지 않는 병렬 워커 구조라는 점에서 [[에이전트-권한-경계-체크리스트]]가 다루는 권한 경계 문제가 그대로 옵니다 — 이 vault가 daily-brief·weekly-review를 예약 실행으로 돌리는 것과 같은 종류의 트레이드오프입니다.

### GitLab 19.4 — Duo Agent Platform에 목표 기반 CLI(`/goal`), MCP 도구 거버넌스 추가
GitLab Duo CLI가 단계별 지시 대신 열린 목표를 주면 로컬에서 스스로 진행을 점검하는 `/goal` 명령(퍼블릭 베타)을 얻었습니다. MCP 서버 도구를 내부 Duo 도구와 같은 자리에서 거버넌스할 수 있게 됐고, 읽기 전용 도구는 기본 항상 허용, 쓰기·삭제 도구는 기본 항상 확인으로 나뉩니다.

- 출처: [GitLab 19.4 release notes — 공식 문서](https://docs.gitlab.com/releases/19/gitlab-19-4-released/) · 2026-09-17
- 신뢰도: 높음 (1차 출처, 공식 릴리스 노트)
- 왜 중요한가: "읽기는 항상 허용, 쓰기는 항상 확인"이라는 기본값 나누기는 [[에이전트-권한-경계-체크리스트]]가 이 vault의 예약 스킬(파일 쓰기 권한을 vault 폴더로 한정하는 것)에 이미 적용한 것과 같은 원칙이 업계 표준 설정으로 굳어지는 사례입니다.
