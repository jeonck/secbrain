## 오늘 하나만 본다면

Claude Code 2.1.290(2026-10-05)이 "scheduled tasks not persisting after conversation compaction" 버그를 고쳤습니다. 이 vault의 daily-brief·weekly-review·consolidate는 전부 예약 실행으로 돌아가므로, 긴 세션이 compaction을 거친 뒤에도 예약이 살아남는지는 직접적인 이해관계가 있는 변화입니다. 같은 릴리스에서 mod의 `tool.check` 훅에 `agentId`와 `ceiling`이 추가된 것도 [[에이전트-권한-경계-체크리스트]]가 다루는 "권한 경계는 선언이 아니라 메커니즘" 기준과 맞닿습니다.

## anthropic

### Claude Code 2.1.290 — 예약 작업 persistence 수정, mod 훅에 agentId/ceiling 추가
10/5 릴리스에서 "scheduled tasks not persisting after conversation compaction" 버그가 수정됐습니다. 또한 mod의 `turn.step` 훅 결과에 `serverToolUses`가, `tool.check` 이벤트에 `agentId`가, mod의 `tool.check` 훅의 question/verdict에 `ceiling`이 추가됐습니다. `claude plugin validate`에 gating hook 검증도 추가됐고, WebFetch가 100,000자 이후 텍스트를 누락하던 버그도 고쳤습니다.
- 출처: [Claude Code 공식 체인지로그](https://code.claude.com/docs/en/changelog) · 2026-10-05
- 신뢰도: 높음 (1차 출처, 공식 체인지로그)
- 왜 중요한가: scheduled task persistence는 이 vault의 모든 예약 스킬(daily-brief 포함) 실행 안정성에 직결됩니다. mod 훅의 `agentId`/`ceiling` 추가는 플러그인이 어떤 에이전트의 어떤 행동까지 승인할 수 있는지를 더 세분화하는 변화로, [[에이전트-권한-경계-체크리스트]] 다음 점검 때 참고할 항목입니다.

## devtools

### GitHub Copilot CLI v1.0.91 — 읽기전용 shell 파이프라인의 "execution-evidence review" 도입
10/1 릴리스에서, 정적으로 완전히 분석 가능한 읽기전용 shell 파이프라인은 "execution-evidence review"로 처리되고, 불완전하거나 바인딩되지 않은 파이프라인은 명시적 승인을 요구하도록 바뀌었습니다. `copilot sandbox ca` 명령으로 프록시 CA 트러스트를 점검·생성·회전할 수도 있게 됐습니다.
- 출처: [github/copilot-cli Release v1.0.91](https://github.com/github/copilot-cli/releases/tag/v1.0.91) · 2026-10-01
- 신뢰도: 높음 (1차 출처, 공식 릴리스 노트)
- 왜 중요한가: "명령이 읽기전용·정적 분석 가능할 때만 자동 승인"이라는 접근은 Claude Code의 권한 규칙과 비교할 만한 설계입니다. [[에이전트-권한-경계-체크리스트]]가 점검하는 "무엇을 자동 승인해도 안전한가" 기준에 직접 참고가 됩니다.
