## 오늘 하나만 본다면

Claude Code v2.1.294(2026-10-08)는 "Block commands that..." 같은 자연어 지시문으로 작성된 `prompt`/`agent` 훅이 실제로는 막아야 할 동작을 막지 못하고 통과시키던 버그를 고쳤습니다. 같은 날 v2.1.295는 훅이 시작 실패·타임아웃·예상 밖 종료 코드를 내면 기본적으로 동작을 **차단**하는 `onFailure: "block"` 옵션을 추가했습니다. [[에이전트-권한-경계-체크리스트]]의 6번 원칙("되돌릴 수 없거나 민감한 액션은 실행 전에 사람 승인을 거치게 한다")은 그 승인 게이트가 설정한 대로 동작한다는 걸 전제로 합니다. 이번 수정은 지시문 기반 훅이 그 전제를 깨고 있었다는 1차 확인이고, `onFailure: "block"`은 훅 자체가 실패했을 때의 기본 동작을 "통과"에서 "차단"으로 뒤집는 설계 변화라 체크리스트에 추가할 만합니다.

## anthropic

### Claude Code v2.1.294/v2.1.295 — 훅이 막아야 할 걸 막지 못하던 버그 수정, 훅 실패 시 기본 차단 옵션 추가
v2.1.294는 "Block commands that..." 식 지시문으로 쓴 `prompt`/`agent` 훅이 막아야 할 동작을 허용하던 버그를 고쳤고, Stop/SubagentStop 훅의 지시문 판단도 더 정확해졌습니다. v2.1.295는 명령·HTTP 훅이 시작 실패·타임아웃·예상 밖 종료 코드를 내면 동작을 차단하는 `onFailure: "block"`을 추가했습니다(기존엔 훅이 죽으면 통과였다는 뜻).
- 출처: [Claude Code 공식 체인지로그](https://code.claude.com/docs/en/changelog) (v2.1.294, v2.1.295) · 2026-10-08
- 신뢰도: 높음 (1차 출처, 공식 체인지로그)
- 왜 중요한가: [[에이전트-권한-경계-체크리스트]]가 승인 게이트의 전제로 깔고 있는 "훅이 설정대로 동작한다"는 가정이 실제로는 지시문 기반 훅에서 깨져 있었다는 사례입니다. 체크리스트를 쓰는 사람이면 명령/HTTP 훅 쪽은 `onFailure: "block"`을 명시적으로 켜야 안전한 기본값이 된다는 점도 반영할 만합니다.

### Managed Agents — `limited` 네트워킹에서 web_fetch가 세션에 등장한 URL만 가져오도록 제한
Anthropic 공식 릴리스 노트(2026-10-07)에 따르면 `limited` 네트워킹 모드에서 `allowed_hosts`가 `web_search`·`web_fetch`에도 적용되도록 범위가 넓어졌고, `web_fetch`는 이제 같은 세션에서 이미 등장한 URL만 가져올 수 있습니다.
- 출처: [Claude Platform 공식 릴리스 노트](https://platform.claude.com/docs/en/release-notes/overview) · 2026-10-07
- 신뢰도: 높음 (1차 출처, 공식 릴리스 노트)
- 왜 중요한가: 에이전트가 임의 URL을 가져오는 걸 네트워크 레벨에서 좁히는 조치라 [[에이전트-권한-경계-체크리스트]]의 "실행 전 범위를 좁힌다" 계열 항목과 맞닿습니다. Managed Agents를 쓰는 구성이 있다면 `allowed_hosts` 설정이 web_fetch까지 커버하는지 다시 확인할 필요가 있습니다.
