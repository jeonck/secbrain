## 오늘 하나만 본다면

Anthropic이 2026-10-07 **Claude Haiku 5.5**(`claude-haiku-5-5`)를 출시했습니다 — 1M 토큰 컨텍스트, 128k 최대 출력, 적응형 사고(adaptive thinking) 지원, 가격은 $0.10/$0.50 per Mtok(입력/출력)입니다. 같은 주 Claude Code v2.1.296(2026-10-09)은 Sonnet 5.5의 캐시 읽기 가격을 백만 토큰당 $0.20에서 $0.10으로 반값 인하했습니다. [[에이전트-비용-구조-정리와-빈틈]]은 "리드(비싼 모델)=판단, 워커(싼 모델)=I/O"라는 패턴만 vault에 확립돼 있고 실측 비용 데이터는 전혀 없다고 짚었는데, 이번 두 가지는 그 패턴에 처음으로 붙는 검증된 1차 숫자입니다 — 특히 [[secbrain-site]]가 단일 모델(claude-sonnet-5 계열)로 돌아간다는 점에서 캐시 읽기 가격 인하는 이 vault 자신의 운영 비용에 직접 영향을 줍니다.

## anthropic

### Claude Haiku 5.5 출시 — Anthropic API 기본 Haiku 모델로
고빈도·저지연 작업을 겨냥한 모델로, 1M 토큰 컨텍스트와 128k 최대 출력, 적응형 사고와 `effort` 파라미터를 지원합니다. Haiku 4.5 코드를 그대로 옮기면 수동 확장 사고(`budget_tokens`)·`temperature`·`top_p`·`top_k`·assistant prefill·구형 `computer_20250124` 도구 조합에서 400 오류가 날 수 있습니다.
- 출처: [Claude Platform 공식 릴리스 노트](https://platform.claude.com/docs/en/release-notes/overview) · 2026-10-07
- 신뢰도: 높음 (1차 출처, 공식 릴리스 노트)
- 왜 중요한가: [[에이전트-비용-구조-정리와-빈틈]]이 말하는 "싼 모델=I/O 워커" 역할에 가격·스펙이 공식으로 들어맞는 모델입니다. [[cog-architecture]]의 리드/워커 구조를 실제로 설계할 때 워커 쪽 기본값으로 검토할 만합니다.

### Claude Code v2.1.296 — Sonnet 5.5 캐시 읽기 가격 반값 인하, 워크플로 전용 서브에이전트 모델 변수 추가
캐시 읽기 가격이 백만 토큰당 $0.20 → $0.10으로 내렸고(기본 입력 가격의 일부), `CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL` 환경 변수로 워크플로 에이전트를 지정한 한 모델로 묶어 실행할 수 있게 됐습니다.
- 출처: [Claude Code 공식 체인지로그](https://code.claude.com/docs/en/changelog) (v2.1.296) · 2026-10-09
- 신뢰도: 높음 (1차 출처, 공식 체인지로그)
- 왜 중요한가: [[secbrain-site]]의 예약 파이프라인(daily-brief·weekly-review 등)은 매 실행마다 CLAUDE.md·스킬 파일을 캐시에서 반복 읽습니다. 캐시 읽기 가격이 반으로 줄면 이 vault 자체의 예약 실행 비용이 그만큼 낮아진다는 뜻이라, "실측 비용 데이터가 vault에 없다"는 기존 빈틈에 구체적으로 적용해볼 만한 숫자입니다.

## agents

### Managed Agents 동적 워크플로우(dynamic workflows, beta)
수백 개의 문서 검토처럼 작업 단위가 많은 일을 에이전트가 워크플로 프로그램으로 처리하도록 하는 베타 기능입니다. 에이전트의 `multiagent` 필드에 `{"type": "multiagent_20261001", "workflows": {"type": "enabled"}}`를 설정하면 켜지고, 진행 상황은 세션 이벤트 스트림의 `workflow_run.*` 이벤트로 확인합니다.
- 출처: [Claude Platform 공식 릴리스 노트](https://platform.claude.com/docs/en/release-notes/overview) · 2026-10-09
- 신뢰도: 높음 (1차 출처, 공식 릴리스 노트)
- 왜 중요한가: "작업 단위가 많을 때 리드가 워크플로를 짜고 워커들이 각 단위를 처리한다"는 설계는 [[cog-architecture]]의 리드/워커 구조를 Anthropic이 플랫폼 기능으로 공식화한 것에 가깝습니다. 이 vault가 언젠가 "노트 100건 일괄 재분류" 같은 대량 작업을 스킬로 만든다면 참고할 만한 1차 사례입니다.
