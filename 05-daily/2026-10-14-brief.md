## 오늘 하나만 본다면

Claude Code 2.1.299~2.1.300(2026-10-14, 같은 날 연속 릴리스)이 권한 관련 구멍 두 곳을 좁혔습니다: 훅이 돌려주는 `updatedInput` 값이 이제 Claude 자신의 입력과 동일한 검증을 거치고, MCP 허용 규칙은 정확히 지정된 서버 이름에만 매칭됩니다(`mcp__a`가 더 이상 `mcp__a__b`를 포함하지 않음). [[에이전트-권한-경계-체크리스트]] 핵심 1("경계는 프롬프트 지시문이 아니라 강제 메커니즘으로 세운다")에 해당하는 구체 사례이며, [[2026-10-13-brief]]가 확인한 GitHub Copilot CLI의 autopilot ask-거부 정식화와 같은 주에 나온 — 벤더들이 느슨했던 기본값을 하나씩 조이는 흐름의 연장입니다.

## anthropic

### Claude Code v2.1.299~v2.1.300 — 훅 입력 검증 강화, MCP 허용 규칙 정밀화
2.1.300(10/14)은 훅이 반환하는 `updatedInput`을 Claude 자신의 입력과 같은 절차로 검증하도록 바꿨고, `claude remote-control`의 `--sandbox`/`--no-sandbox` 플래그를 없애고 설정의 `sandbox.enabled`로 통합했습니다. 2.1.299(10/14)는 MCP 허용 규칙이 지정된 서버 이름에만 정확히 매칭되도록 좁혔고(이중 밑줄 서버명은 `mcp__<server>__*` 사용 필요), 200K 토큰 넘는 대화에 대해 유휴 약 54분 후·1시간 캐시 만료 전 자동 압축(idle compaction)을 추가했습니다.
- 출처: [Claude Code 공식 체인지로그](https://code.claude.com/docs/en/changelog) (v2.1.299, v2.1.300) · 2026-10-14
- 신뢰도: 높음 (1차 출처, 공식 체인지로그)
- 왜 중요한가: [[에이전트-권한-경계-체크리스트]] 핵심 1이 요구하는 "강제 메커니즘"에 해당하는 두 보수 사례. 훅의 반환값을 무검증으로 신뢰하면 훅 자체가 우회 경로가 되고, 서버 이름 접두사 매칭은 의도치 않은 과허용으로 이어질 수 있었습니다. 같은 주 [[2026-10-13-brief]]가 짚은 GitHub Copilot CLI의 autopilot ask-거부 정식화와 더불어, 서로 다른 벤더가 같은 방향(기본값을 거부·정밀 매칭 쪽으로)으로 움직인 사례로 묶을 수 있습니다.

## devtools

### GitHub Copilot CLI v1.0.98 — Gemini 4 Argon 지원, 명령 훅·세션 재개 신뢰성 개선
10/14 정식 릴리스로 Gemini 4 Argon 모델 지원이 추가됐고, Node에서 자식 프로세스 종료 신호가 유실돼도 명령 훅이 끝까지 처리되도록 고쳤습니다. 분할 화면 전환 후 MCP 상태·`/mcp` 명령이 활성 세션과 어긋나지 않게 됐고, 세션 재개 시 중단된 대기 중 권한 요청은 무시하고 활성 요청만 이어가도록 바뀌었습니다. [[2026-10-13-brief]]가 정식 승격을 확인한 autopilot의 preToolUse "ask" 거부 처리는 이번 버전에도 그대로 유지됩니다.
- 출처: [github/copilot-cli Releases](https://github.com/github/copilot-cli/releases) (v1.0.98) · 2026-10-14
- 신뢰도: 높음 (1차 출처, 공식 릴리스 페이지)
- 왜 중요한가: "세션 재개 시 중단된 대기 중 권한 요청을 무시한다"는 동작은, 무인 실행에서 오래된 승인 대기가 좀비처럼 남아 모호한 상태를 만드는 문제를 줄입니다 — [[에이전트-권한-경계-체크리스트]]가 다뤄온 무인 폴백 논의와 결이 같은 작은 보완입니다.

## agents

### CrewAI v1.15.28 — eval 중단 지점 리포트, LiteLLM 카탈로그 기반 컨텍스트 윈도우
10/14 릴리스로 `crewai eval`이 평가가 정확히 어느 모델에서 멈췄는지 리포트하도록 바뀌었고, 모델 컨텍스트 윈도우 값을 LiteLLM 카탈로그에서 가져오도록 변경했습니다. 같은 버전에서 재개된 사람 피드백을 플로우가 제대로 학습하지 못하던 버그, `crewai deploy` 실패 보고·락파일 검사 문제를 포함해 13건의 버그가 함께 수정됐습니다.
- 출처: [CrewAI 공식 체인지로그](https://docs.crewai.com/en/changelog) (v1.15.28) · 2026-10-14
- 신뢰도: 높음 (1차 출처, 공식 체인지로그)
- 왜 중요한가: [[2026-10-13-brief]]가 짚은 v1.15.27("중단 이유 기록 + 모델별 비용·시간 추적")에 "정확히 어디서 멈췄는가"가 구체화되어 붙었습니다. 실측 비용·실패 지점 가시성 부재 문제에 프레임워크가 연속으로 대응하는 흐름입니다.
