## 오늘 하나만 본다면

Claude Code 2.1.301(10/15)에 추가된 `CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS`는 무인(unattended) 재시도 모드가 멀리 떨어진 사용량 한도 리셋 시각까지 그냥 기다리게 두지 않도록 상한을 거는 설정입니다. 이 vault 자체가 예약 실행(daily-brief, weekly-review 등)으로 돌아가는 무인 운영 사례라 직접 걸립니다. 같은 날 GitHub Copilot CLI 1.0.99는 `/sandbox`를 세션 단위로 켤 수 있게 하고 GitHub 설치 링크로 검증된 Skill·플러그인을 받도록 바꿨는데, 두 벤더가 같은 날 "무인 실행의 경계를 더 세밀하게 통제"하는 방향으로 움직인 점이 [[에이전트-권한-경계-체크리스트]]와 바로 이어집니다.

## anthropic

### Claude Code v2.1.301 — 무인 재시도 워치독, 훅 `.catch` 범위 축소, Grep/Glob 오류 가시화
`CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS`가 추가돼 무인 재시도 모드가 먼 사용량 한도 리셋 시각을 그냥 기다리는 상황을 상한으로 막을 수 있게 됐습니다. 모드 훅의 `.catch`는 이제 훅이 예외를 던지거나 타임아웃됐을 때만 실행되도록 범위가 좁혀졌고, Grep/Glob은 검색 프로그램 자체가 실패했을 때 "결과 없음"이 아니라 오류로 보고하도록 고쳐졌습니다(총 37건 수정 중 일부). OpenTelemetry에는 `tool_decision` 이벤트에 `classifier_verdict`, `permission_mode`, `classifier_category` 필드가 붙었습니다.
- 출처: [Claude Code 공식 체인지로그](https://code.claude.com/docs/en/changelog) (v2.1.301) · 2026-10-15
- 신뢰도: 높음 (1차 출처, 공식 체인지로그)
- 왜 중요한가: 이 vault의 daily-brief·weekly-review는 예약(무인) 실행입니다. 재시도가 먼 리셋 시각까지 무제한 대기하는 문제는 바로 이런 구조에서 실제로 발생할 수 있는 실패 모드이고, 이번 워치독은 그 상한을 거는 보수책입니다. "결과 없음"과 "검색 자체가 실패"를 구분하는 Grep/Glob 수정도 같은 결의 신뢰성 보강입니다.

## devtools

### GitHub Copilot CLI v1.0.99 — 세션별 샌드박스 토글, GitHub 링크로 검증된 Skill·플러그인 설치
10/15에 연속으로 나온 1.0.99-0, 1.0.99-1 프리릴리스가 `/sandbox`를 세션 단위로 켤 수 있게 했고, 신뢰된(trusted) 저장소의 플러그인은 자동으로 업데이트되도록 바꿨습니다. GitHub 설치 링크를 통해 검증된 Skill과 플러그인을 설치하는 기능과, 일회성 프롬프트 모드 세션용 `--trust-folder` 옵션도 추가됐습니다. 샌드박스는 기본적으로 로컬 네트워크 접근을 허용하도록 바뀌었고, `.github/instructions`의 경로별 지시 파일이 자동 적용됩니다.
- 출처: [github/copilot-cli Releases](https://github.com/github/copilot-cli/releases) (v1.0.99-0, v1.0.99-1) · 2026-10-15
- 신뢰도: 높음 (1차 출처, 공식 릴리스 페이지)
- 왜 중요한가: [[2026-10-13-brief]]가 짚은 autopilot의 "ask" 거부 정식화, [[2026-10-14-brief]]가 짚은 Claude Code의 MCP 허용 규칙 정밀화와 같은 흐름 — 샌드박스·설치 경로의 신뢰 경계를 더 세밀하게 쪼개는 보수책입니다. 다만 "샌드박스 기본값이 로컬 네트워크 접근을 허용"한다는 변경은 방향이 반대(완화)라서, [[에이전트-권한-경계-체크리스트]] 관점에서는 득실을 따로 봐야 할 항목입니다.
