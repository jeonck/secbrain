## 오늘 하나만 본다면

Claude Code 2.1.302(10/16)는 "중단된 예약 루틴(scheduled routine) 실행이 1시간 이상 뒤에 처음부터 다시 돌면서, 같은 보고를 두 번 올리는 등 작업이 반복될 수 있던" 버그를 고쳤습니다. 이 vault의 daily-brief·weekly-review가 정확히 그 구조 — GitHub Actions 예약 루틴으로 커밋을 남기는 파이프라인([[secbrain-site]]) — 라서 직접 걸리는 수정입니다. 같은 릴리스가 `claude -p`/Agent SDK/데스크톱/VS Code에서 fork 서브에이전트(`subagent_type: "fork"`)를 기본으로 켠 것도 이 스킬이 쓰는 실행 방식과 바로 맞닿습니다.

## anthropic

### Claude Code v2.1.302 — 예약 루틴 중복 실행 버그 수정, fork 서브에이전트 기본값 전환
"부분 실패한 예약 루틴 실행이 1시간 이상 뒤 처음부터 재실행되며 같은 보고를 두 번 올리는 등 작업을 반복할 수 있던" 버그가 고쳐졌습니다. 또한 fork 서브에이전트(`subagent_type: "fork"`)가 터미널에서만이 아니라 `claude -p`, Agent SDK, 데스크톱 앱, VS Code에서도 기본으로 켜지도록 바뀌었고(`CLAUDE_CODE_FORK_SUBAGENT=0`으로 끌 수 있음), 데스크톱·VS Code의 메인 대화 서브에이전트는 터미널처럼 항상 백그라운드로 돌게 바뀌었습니다.
- 출처: [Claude Code 공식 체인지로그](https://code.claude.com/docs/en/changelog) (v2.1.302) · 2026-10-16
- 신뢰도: 높음 (1차 출처, 공식 체인지로그)
- 왜 중요한가: 예약 루틴 중복 실행 버그는 이 vault의 daily-brief·weekly-review 파이프라인([[secbrain-site]])이 겪을 수 있던 실제 실패 모드였습니다. fork 서브에이전트 기본값 전환은 지금 이 스킬 실행에서 Agent 도구를 쓰는 방식에 직접 영향을 줍니다.

## devtools

### GitHub Copilot CLI v1.0.99-3 / v1.0.100-0 / v1.0.100-1 — 텔레메트리 차단 플래그, 샌드박스 프록시 인증서 처리
10/16에 연속으로 나온 세 프리릴리스에서 클라이언트 텔레메트리 업로드를 끄는 플래그가 추가됐고, 샌드박스 프록시가 마스킹된 호스트가 바뀔 때 인증서를 갱신하도록 안내하며 `HTTPS_PROXY`/`HTTP_PROXY` 환경변수를 더 우선 참조하도록 바뀌었습니다. 관리형(managed) 플러그인 업데이트는 정책이 바뀌면 이미 열린 세션에도 적용되도록 변경됐습니다.
- 출처: [github/copilot-cli Releases](https://github.com/github/copilot-cli/releases) (v1.0.99-3, v1.0.100-0, v1.0.100-1) · 2026-10-16
- 신뢰도: 높음 (1차 출처, 공식 릴리스 페이지)
- 왜 중요한가: [[2026-10-15-brief]]가 짚은 세션별 샌드박스 토글·신뢰 저장소 설치에 이어, 텔레메트리 차단과 프록시 인증서 처리까지 권한·신뢰 경계를 세분화하는 흐름이 계속됩니다. [[에이전트-권한-경계-체크리스트]] 관점에서는 "관리형 정책이 이미 열린 세션에도 소급 적용"된다는 점이 눈여겨볼 변화입니다.
