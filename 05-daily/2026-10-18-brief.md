## 오늘 하나만 본다면

LangGraph 1.2.16(10/16)이 interrupt/resume 경로의 버그 묶음을 고쳤습니다. 핵심은 "재실행 시 이미 끝낸 작업을 다시 돌리거나 pending writes를 중복 저장"하던 문제들입니다 — 서브그래프가 resume 시 이미 완료한 태스크를 skip하지 않고 다시 돌던 버그, resume한 종료 실행이 pending writes를 한 번이 아니라 여러 번 저장하던 버그, 잘못된 resume 값이 형제 태스크 완료를 막던 버그. 이 vault가 daily-brief·weekly-review를 GitHub Actions 예약 루틴으로 돌리는 구조([[secbrain-site]])라서, "중단·재실행이 작업을 중복시키지 않아야 한다"는 요구는 [[2026-10-16-brief]]가 짚은 Claude Code의 예약 루틴 중복 실행 버그 수정과 같은 줄기입니다. 멀티 에이전트 프레임워크 쪽에서도 같은 종류의 멱등성 버그가 계속 나온다는 뜻입니다.

## agents

### LangGraph 1.2.16 — interrupt/resume 중복 실행·중복 저장 버그 수정, PostgresSaver prune 추가
10/16에 나온 LangGraph 1.2.16은 주로 버그 수정 릴리스입니다. 잘못된 resume 값이 형제 태스크의 완료를 막던 문제, resume한 `Command`가 상태 업데이트를 여러 번 적용하던 문제, 서브그래프가 resume 시 이미 끝낸 태스크를 재실행하던 문제, resume한 종료 실행이 pending writes를 중복 저장하던 문제가 고쳐졌습니다. `DeltaChannel`이 plain reducer로 전환될 때 기존 값을 보존하도록도 바뀌었습니다. 새 기능으로는 `PostgresSaver`/`AsyncPostgresSaver`에 `prune` 메서드가 추가됐습니다(checkpoint-postgres 3.2.0, checkpoint-sqlite 3.1.2, prebuilt 1.1.1도 같은 날 함께 릴리스).
- 출처: [LangGraph 1.2.16 릴리스 노트](https://github.com/langchain-ai/langgraph/releases/tag/1.2.16) · 2026-10-16
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스)
- 왜 중요한가: interrupt/resume 시 작업이 중복되지 않아야 한다는 요구는 이 vault의 예약 실행 파이프라인([[secbrain-site]])이 10/16에 겪었던 것과 같은 종류의 버그([[2026-10-16-brief]])입니다. 멀티 에이전트 오케스트레이션을 도입할 때 체크리스트([[에이전트-권한-경계-체크리스트]])에 "중단 후 재실행이 멱등적인가"를 넣을 근거가 됩니다.

## anthropic

### Compliance API — 사용자 "Instructions for Claude" 조회 베타, Claude Code v2.1.303 버그 수정
10/15에 Claude Enterprise의 Compliance API가 각 조직 멤버가 claude.ai에 저장한 "Instructions for Claude"와 Cowork의 "Global instructions" 텍스트를 조회하는 기능을 베타로 열었습니다(`GET /v1/compliance/organizations/{org_uuid}/user_preferences`, `read:compliance_user_data` 스코프 필요). 같은 주 10/18에는 Claude Code v2.1.303이 나왔는데, 공식 체인지로그에는 "버그 수정 및 안정성 개선"이라고만 적혀 있고 세부 항목은 공개되지 않았습니다.
- 출처: [Claude Platform 릴리스 노트](https://platform.claude.com/docs/en/release-notes/api) · 2026-10-15, [Claude Code 체인지로그](https://code.claude.com/docs/en/changelog) (v2.1.303) · 2026-10-18
- 신뢰도: 높음 (1차 출처, 공식 릴리스 노트·체인지로그) — 다만 v2.1.303은 세부 내용이 공개되지 않아 무엇이 바뀌었는지는 확인 불가
- 왜 중요한가: Compliance API는 Enterprise 관리자가 조직 구성원의 개인화 설정을 감사할 수 있게 하는 변화로, 이 vault 자체에는 직접 해당하지 않지만 [[2026-10-17-brief]]의 OpenTelemetry 트레이싱과 같은 "조직이 Claude 사용을 들여다볼 수 있게" 하는 흐름의 연장입니다.
