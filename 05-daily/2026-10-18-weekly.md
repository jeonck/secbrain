## 발견한 패턴

### "멈췄다가 다시 돌 때 끝낸 일을 중복하지 않는다" — 무인 재실행의 멱등성
이번 주 브리프 6건 중 4건이 같은 결의 문제를 다뤘다. [[2026-10-15-brief]]는 Claude Code의 무인 재시도가 먼 사용량 한도 리셋 시각까지 무제한 대기하지 않도록 상한(`CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS`)을 걸었고, [[2026-10-16-brief]]는 "부분 실패한 예약 루틴이 1시간 뒤 처음부터 재실행되며 같은 보고를 두 번 올리던" 버그를 고쳤다고 적었다 — 이건 이 vault 자신이 daily-brief·weekly-review를 GitHub Actions 예약 루틴으로 돌리는 구조([[secbrain-site]])와 정확히 같은 모양의 실패 모드다. [[2026-10-17-brief]]의 Messages API·Managed Agents OpenTelemetry 트레이싱 베타는 이런 무인 실행을 사후에 들여다볼 수단이고, [[2026-10-18-brief]]는 LangGraph 1.2.16이 "서브그래프가 resume 시 이미 끝낸 태스크를 재실행"하거나 "pending writes를 중복 저장"하던 버그를 고쳤다고 적으며 10-16과 같은 버그 클래스라고 스스로 연결했다.

가설 한 문장: 이 네 건이 벤더·프레임워크 네 곳(Claude Code, Anthropic Platform, LangGraph)에 걸쳐 거의 동시에 나온 건, 무인 오케스트레이션이 흔해지면서 "중단-재시작이 중복을 만들지 않는가"가 "승인 게이트가 있는가"(지난주 패턴)만큼 흔한 결함 클래스로 떠올랐다는 뜻일 수 있다.

## 도메인을 가로지른 연결

[[에이전트-권한-경계-체크리스트]](03-resources)의 핵심 1~6은 전부 "누가 실행을 승인·거부하는가"를 다루지만, "중단 후 재실행이 기존 작업을 중복하지 않는가"라는 이번 주 패턴에 해당하는 항목은 없다. 그런데 이 틈을 메울 실제 증거가 바로 [[secbrain-site]](01-projects) 자신에게 있다 — 이 프로젝트가 돌리는 예약 파이프라인이 [[2026-10-16-brief]]가 기술한 버그와 같은 구조이고, Claude Code 측에서 10-16에 그 버그가 이미 고쳐졌다. `03-resources`의 체크리스트와 `01-projects`의 실제 운영 구조가 같은 결함 클래스를 가리키고 있는데, 체크리스트 쪽에는 아직 반영되지 않았다.

참고로 지난주([[2026-10-11-weekly]])가 지적한 "게이트가 실제로 버티는가"라는 핵심 6의 신뢰성 질문도 이번 주 [[2026-10-13-brief]](Copilot CLI autopilot ask→거부 전환)·[[2026-10-14-brief]](Claude Code 훅 입력 검증·MCP 매칭 정밀화)로 계속 확인됐다 — 즉 지금 체크리스트에는 반영을 기다리는 관찰이 최소 두 갈래(게이트 신뢰성, 재실행 멱등성) 쌓여 있다.
