## 오늘 하나만 본다면

Claude Enterprise의 [Inference hooks](https://platform.claude.com/docs/en/manage-claude/inference-hooks)가 10/20에 베타를 졸업했습니다. 모든 거버넌스 대상 프롬프트와(옵션 시) 도구 호출을 추론 전에 조직이 운영하는 AI 보안 서버로 보내 allow/deny 판정을 받는 구조로, claude.ai·Cowork·Claude Code·Claude Tag 전체에 적용됩니다. [[secbrain-site]]처럼 사람 개입 없이 GitHub Actions 러너가 스킬을 자동 실행하는 구조와는 반대 극단 — 사람이 만든 외부 서버가 매 요청을 승인/거부하는 모델입니다. 어제 다룬 mod `tool.check`의 `decider: "person"`과 같은 방향(추론/도구호출을 인간 또는 외부 판정자에게 묶기)의 변화로, [[에이전트-권한-경계-체크리스트]]에 "인라인 추론 거버넌스(허용/거부 서버)를 쓰는가" 항목을 추가할 근거가 됩니다.

## agents

### GitHub Copilot CLI 1.0.101 — dynamic workflow subagent 구조화 출력 정식 반영 (10/20)
어제 프리릴리스(1.0.101-0)였던 지원 모델 대상 structured output이 10/20 정식 릴리스로 올라왔습니다. Assisted Permissions의 승인 결정을 안내하는 `assistedApprovalInstructions` 설정도 함께 정식화됐고, MCP 인증 복구(거부된 캐시 토큰에서 Entra 로그인 복구)와 세션 재개 속도 개선이 포함됐습니다.

- 출처: [GitHub Copilot CLI v1.0.101 릴리스](https://github.com/github/copilot-cli/releases/tag/v1.0.101) · 2026-10-20
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스)
- 왜 중요한가: dynamic workflow subagent의 출력 구조화가 프리릴리스를 벗어나 안정판에 들어왔다는 것은, 이 vault가 Workflow로 멀티 에이전트 작업을 돌릴 때 겪는 것과 같은 문제(서브에이전트 출력을 신뢰할 수 있게 소비하기)에 쓸 수 있는 패턴이 실전 투입 단계에 왔다는 뜻입니다.

## anthropic

### Claude Enterprise — Inference hooks 베타 졸업 (10/20)
조직이 운영하는 AI 보안 서버가 모든 거버넌스 대상 프롬프트를 추론 전에 HTTPS POST로 받아 allow/deny 판정(기본 타임아웃 5초)을 내리고, "도구 호출 검증"을 켜면 도구 호출도 실행 전에 검사합니다. 판정은 Standard Webhooks 서명으로 검증되며, 거부는 조직의 Activity Feed에 기록됩니다. Bedrock·Google Cloud에서는 아직 지원되지 않습니다.

- 출처: [Inference hooks 문서](https://platform.claude.com/docs/en/manage-claude/inference-hooks) · 2026-10-20
- 신뢰도: 높음 (1차 출처, 공식 문서)
- 왜 중요한가: [[secbrain-site]]의 완전 자동 실행 파이프라인과 대조되는 거버넌스 모델입니다 — 외부 서버가 매 추론을 사람 대신 승인/거부. [[에이전트-권한-경계-체크리스트]]에 추가할 패턴 후보.

### Claude Code v2.1.304 — Code Review 레벨, 조직 전체 리포 리뷰, mod tool.check decider:"person"
10/19 릴리스. mod의 `tool.check` 응답에 `decider: "person"`을 지정하면 오직 권한 다이얼로그나 호스트 콜백만 승인할 수 있게 제한되고, `tool.check` 이벤트에 `e.isReadOnly`가 추가됐습니다. Code Review에 Quick/Standard/Deep 레벨과 GitHub organization 전체 저장소 리뷰 옵션이 생겼고, `/auto-mode-setup`이 Bedrock·Vertex·Foundry·텔레메트리 비활성 세션까지 확장됐습니다. 43건의 버그 수정도 포함(Linux sandbox `denyRead` glob 문제, `--worktree` 종료 시 커밋 손실 등).

- 출처: [Claude Code 체인지로그](https://code.claude.com/docs/en/changelog) · 2026-10-19
- 신뢰도: 높음 (1차 출처, 공식 체인지로그)
- 왜 중요한가: `decider: "person"` 제약은 [[secbrain-site]] 파이프라인처럼 사람 개입 없이 Actions 러너가 자동 실행되는 구조에 직접 닿습니다 — mod가 `tool.check`을 자체 승인하지 못하게 막는 경계선. [[에이전트-권한-경계-체크리스트]]에 "tool.check decider 제약을 쓰는가" 항목을 추가할 근거가 됩니다.

### Claude Platform — Opus 5.5 Fast mode, 베타 졸업 (10/15)
Claude Opus 5.5의 Fast mode가 research preview를 벗어나 Start/Build/Scale 티어에서 기본 rate limit을 받게 됐습니다. `fast-mode-2026-02-01` 베타 헤더는 이제 선택사항입니다(보내도 동작은 유지). Opus 5·Opus 4.8의 Fast mode는 여전히 research preview로 남아 헤더가 필요합니다.

- 출처: [Claude Platform 릴리스 노트](https://platform.claude.com/docs/en/release-notes/overview) · 2026-10-15
- 신뢰도: 높음 (1차 출처, 공식 릴리스 노트)
- 왜 중요한가: [[2026-10-18-brief]]가 다룬 Compliance API와 같은 날 나온 항목으로, Opus 계열을 쓸 경우 베타 헤더 없이도 fast mode 혜택을 받을 수 있다는 실질적 변화입니다.
