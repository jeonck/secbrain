## 오늘 하나만 본다면

Anthropic이 10/21에 API 버전 `2026-10-21`을 내면서 Python·TypeScript·C#·Go·Java·PHP·Ruby SDK와 `ant` CLI를 일괄 메이저 버전으로 올렸습니다(Python 2.0.0, TypeScript 1.0.0 등). 새 버전은 API 버전과 무관한 자체 breaking change를 포함하고, 라이선스가 MIT에서 Apache 2.0으로 바뀌었습니다. 이 vault의 자동화는 `anthropics/claude-code-action@v1`을 통해 Claude Code를 호출하는 구조([[secbrain-site]])라 액션이 내부적으로 올리는 SDK 버전에 따라 영향이 갈립니다 — 당장 손볼 것은 없지만, 액션이 다음에 새 SDK 메이저로 넘어갈 때 breaking change 목록을 확인할 근거로 남겨둡니다.

## anthropic

### Claude Code v2.1.307 — API 버전 2026-10-21 지원, `claude_code.safety_event` 텔레메트리 추가 (10/21)
`/claude-api api-version` 커맨드로 API 버전 `2026-10-21`을 지정할 수 있게 됐고, 새 OpenTelemetry 이벤트 `claude_code.safety_event`가 추가됐습니다. MCP·모델 전환·헤드리스 모드 관련 다수 버그도 함께 고쳐졌습니다.

- 출처: [Claude Code 릴리스 v2.1.307](https://github.com/anthropics/claude-code/releases) · 2026-10-21
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스)
- 왜 중요한가: `safety_event` 텔레메트리는 [[에이전트-권한-경계-체크리스트]]의 핵심 5번("경보가 울리면 멈춘다")이 다루는 "이상 신호 감지" 쪽에 쓸 수 있는 신호원입니다. 다만 체크리스트의 "하지 말 것" 2번째 규칙대로, 이 기능 하나만으로 vault 정책을 바로 바꾸지는 않습니다.

### 사용자 프로필 enforcement 필드 — 조직 전체가 아닌 최종 고객 단위 제재 (10/20)
`enforcement_status`·`enforcement_actions` 필드가 사용자 프로필에 추가돼, Anthropic이 특정 최종 고객을 제재했는지 조회·필터링할 수 있게 됐습니다. API 요청을 최종 고객 단위로 태그하면 조직 전체가 아니라 해당 고객에게만 제재가 적용됩니다.

- 출처: [Anthropic 릴리스 노트](https://platform.claude.com/docs/en/release-notes/overview) · 2026-10-20
- 신뢰도: 높음 (1차 출처, 공식 릴리스 노트)
- 왜 중요한가: 제재 단위를 세분화하는 구조로, 이 vault가 직접 쓰는 기능은 아니지만 멀티테넌트 서비스를 운영할 때 참고할 패턴입니다.

## agents

### GitHub Copilot CLI 1.0.102 — subagent가 커스텀·MCP 도구 승인을 따르게 됨 (10/21)
Prompt 모드가 managed Auto 모델 선택을 따르게 됐고, subagent 실행이 커스텀 도구·MCP 도구의 승인 설정을 그대로 적용받게 됐습니다. 플러그인 마켓플레이스가 git 서브디렉터리 소스를 지원하고, 샌드박스에서 장시간 실행 명령과 프록시(NO_PROXY/ALL_PROXY) 처리가 고쳐졌습니다.

- 출처: [GitHub Copilot CLI v1.0.102 릴리스](https://github.com/github/copilot-cli/releases/tag/v1.0.102) · 2026-10-21
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스)
- 왜 중요한가: subagent가 상위 세션의 도구 승인 설정을 상속하도록 만든 변화는 [[에이전트-권한-경계-체크리스트]] 핵심 6번(민감 액션은 승인을 거치게 한다)과 같은 방향입니다 — 어제 다룬 1.0.101의 구조화 출력([[2026-10-20-brief]])에 이어, 같은 주에 같은 제품이 승인 경계까지 손댔다는 점에서 일회성이 아니라 연속된 보강으로 봅니다.

- 신뢰도: 높음 (1차 출처, 공식 릴리스 페이지)
- 왜 중요한가: 프로세스 목록으로 시크릿이 새는 것은 [[2026-10-16-brief]]·[[2026-10-18-brief]]에서 추적해 온 Zed 릴리스 연속선상의 문제이자, [[에이전트-권한-경계-체크리스트]]가 다루는 "불필요한 노출 표면" 종류의 결함입니다.
