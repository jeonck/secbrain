## 오늘 하나만 본다면

Claude Code v2.1.310(10/23)은 Linux에서 Ubuntu AppArmor가 user namespace를 제한해 bubblewrap이 샌드박스를 시작하지 못할 때, `/sandbox`와 시작 경고가 원인과 해제 방법을 안내하도록 바꿨습니다. 동시에 Bedrock·Vertex·Foundry나 텔레메트리·비필수 트래픽이 꺼진 제한된 환경에서도 Monitor 도구와 플러그인 모니터를 쓸 수 있게 됐습니다. 10/20(Inference hooks 베타 졸업)→10/21(API 버전·safety_event)→10/22(샌드박스 탈출 3건 수정, rm/rmdir 즉시 거부)에 이어 나흘째, 같은 제품이 "샌드박스·권한 경계가 실제로 작동하는가"를 계속 다듬고 있습니다. [[에이전트-권한-경계-체크리스트]]가 전제하는 샌드박스 신뢰도를 꾸준히 올려주는 방향입니다.

## anthropic

### Claude Code v2.1.310 — Linux AppArmor 샌드박스 차단 안내 추가, 제한 환경에서 Monitor 도구 사용 가능 (10/23)
Ubuntu의 AppArmor가 user namespace를 제한해 bubblewrap 샌드박스가 시작되지 않을 때, `/sandbox`와 시작 경고가 원인과 해제 방법을 설명합니다. Bedrock·Vertex·Foundry, 텔레메트리 비활성 환경에서도 Monitor 도구·플러그인 모니터를 쓸 수 있게 됐고(해당 환경에서는 긴 포그라운드 sleep도 차단), 게이트웨이가 `effort-2025-11-24` 베타 값을 거부해 요청이 실패하던 문제와 Windows에서 Git Bash가 없을 때 PreToolUse/PermissionRequest 훅이 도구 호출을 통과시키던 문제도 고쳤습니다.

- 출처: [Claude Code 릴리스 v2.1.310](https://github.com/anthropics/claude-code/releases/tag/v2.1.310) · 2026-10-23
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스)
- 왜 중요한가: AppArmor 제한 안내는 샌드박스가 "조용히 실패"하지 않고 원인을 알려준다는 점에서 [[에이전트-권한-경계-체크리스트]]의 "경계가 실제로 작동하는지 확인 가능해야 한다"는 방향과 맞습니다. Windows 훅 우회 수정은 어제(10/22) 다룬 샌드박스 탈출 수정 3건과 같은 성격의 결함입니다.

### GitHub Copilot CLI v1.0.104-0/1 — Assisted Permissions 실험 플래그 제거, Auto 설정 실패 시 기본값 폴백 (10/23, 프리릴리스)
1.0.104-0은 Assisted Permissions를 실험 모드를 켜지 않아도 쓸 수 있게 했고, 저장된 Auto 모델 설정을 더 이상 쓸 수 없을 때 매 턴 실패하는 대신 기본 설정으로 대체합니다. 뒤이은 1.0.104-1은 "Fixes and changes"로만 기록돼 세부 내용이 공개되지 않았습니다. 둘 다 프리릴리스로, 안정판(Latest)은 여전히 10/22의 1.0.103입니다.

- 출처: [GitHub Copilot CLI 릴리스](https://github.com/github/copilot-cli/releases) · 2026-10-23
- 신뢰도: 중간 (1차 출처이나 프리릴리스 — 1.0.104-1은 변경 내용 미공개)
- 왜 중요한가: Assisted Permissions가 실험 플래그를 벗어나는 것은 승인 흐름이 기본 경로로 들어온다는 신호입니다. 10/20~22 사흘 연속 다룬 같은 제품의 승인·샌드박스 경계 변화([[2026-10-22-brief]])의 연속선상이라, 프리릴리스가 안정판에 반영되는 시점을 확인할 근거로 남깁니다.
