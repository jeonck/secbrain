## 오늘 하나만 본다면

Claude Code v2.1.312(10/27)은 매우 큰 `CLAUDE.md`·규칙 파일·`@`-포함 파일을 하위 디렉터리에서 **일부만 읽고 덮어쓰던 문제**를 고쳤습니다. 이제는 Write가 전체를 읽거나 편집으로 수정하도록 요구합니다. 이 vault는 루트 `CLAUDE.md`와 `.claude/skills/*/SKILL.md`로 동작이 전부 정의되는 구조이므로([[secbrain-site]]), 이 버그는 과거 어느 시점엔가 조용히 영향을 줬을 수 있는 결함이었습니다. 같은 주, Anthropic은 이 `SKILL.md` 형식 자체인 **Agent Skills**를 Agentic AI Foundation(AAIF)에 기부해 — 이름·로고·GitHub 조직·agentskills.io 도메인까지 — Anthropic 단독 소유에서 Linux Foundation 산하 중립 표준으로 옮겼습니다. 이 vault의 스킬 폴더 구조가 의존하는 형식의 거버넌스가 바뀐 셈입니다.

## anthropic

### Claude Code v2.1.312 — 큰 CLAUDE.md/규칙 파일 부분 읽기로 덮어쓰던 문제 수정, VS Code 조직 정책 미반영 버그 수정 (10/27)
매우 큰 `CLAUDE.md`, 규칙 파일, `@`-포함 파일을 하위 디렉터리에서 일부만 보고 덮어쓰던 문제가 고쳐졌습니다. 이제 Write가 전체 파일을 읽거나 Edit을 쓰도록 요구합니다. 같은 릴리스에서 VS Code 확장은 로그인 후 관리 설정·조직 정책이 세션 나머지 동안 반영되지 않던 문제도 고쳤고, Bash `cd`로 저장소 깊은 곳으로 이동한 뒤 디렉터리별 스킬을 찾지 못하던 문제도 수정했습니다.

- 출처: [Claude Code 릴리스 v2.1.312](https://github.com/anthropics/claude-code/releases/tag/v2.1.312) · 2026-10-27
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스)
- 왜 중요한가: 이 vault는 루트 `CLAUDE.md`와 폴더별 `SKILL.md`로 동작이 정의되는데([[secbrain-site]], [[cog-architecture]]), "큰 규칙 파일을 일부만 읽고 덮어씀"은 정확히 이 구조에서 조용한 손상을 일으킬 수 있는 결함 종류입니다. [[에이전트-권한-경계-체크리스트]]가 전제하는 "규칙 파일이 온전히 적용된다"는 가정과 직결됩니다.

## agents

### Anthropic, Agent Skills를 Agentic AI Foundation에 기부 (10/22)
Anthropic이 AI 에이전트에게 특정 작업·분야의 절차를 가르치는 개방형 표준 **Agent Skills**(SKILL.md 파일 + 스크립트·참고자료 폴더 구조)를 Linux Foundation 산하 Agentic AI Foundation(AAIF, Anthropic이 Block·OpenAI와 공동 설립)에 기부했습니다. 이름·로고·GitHub 조직·agentskills.io 도메인도 함께 넘겼습니다. 2025년 12월 공개 이후 ChatGPT·Cursor·GitHub Copilot·VS Code 등 70여 개 플랫폼이 採用했고, 스킬은 100만 개 이상 게시·약 2억 8천만 회 설치됐습니다. 로드맵에는 버전 관리된 릴리스, 공식 제안 절차, 보안 지침이 포함됩니다.

- 출처: [Donating Agent Skills to the Agentic AI Foundation](https://www.anthropic.com/news/donating-agent-skills-to-the-agentic-ai-foundation) · 2026-10-22
- 신뢰도: 높음 (1차 출처, Anthropic 공식 뉴스룸)
- 왜 중요한가: 이 vault의 `.claude/skills/*/SKILL.md` 구조가 바로 이 표준입니다. 소유권이 단일 기업에서 중립 재단으로 옮겨가면 향후 스킬 형식에 버전·보안 규약이 생길 수 있어, [[에이전트-권한-경계-체크리스트]]를 갱신할 근거가 될 수 있습니다.

### GitHub Copilot CLI v1.0.104 — Assisted Permissions 정식 기본 제공, Autopilot 백그라운드 작업 대기 방식 변경 (10/27, Latest)
실험 플래그 없이 Assisted Permissions를 쓸 수 있게 됐고, 저장된 Auto 모델 설정을 더 이상 쓸 수 없을 때 매 턴 실패하는 대신 기본 설정으로 대체합니다. 대화형·SDK Autopilot 세션은 `COPILOT_TASK_WAIT_TIMEOUT_SECONDS`가 지나도 연결된 백그라운드 작업이 끝날 때까지 중단되지 않습니다(`-p --autopilot`은 예외).

- 출처: [GitHub Copilot CLI 릴리스](https://github.com/github/copilot-cli/releases) · 2026-10-27
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스, 정식 버전)
- 왜 중요한가: 10/20~23 사흘 연속 다뤘던([[2026-10-23-brief]]) Assisted Permissions 실험 단계 이탈이 정식판에 반영된 시점입니다. 승인 흐름이 기본 경로로 들어온 것은 [[에이전트-권한-경계-체크리스트]]의 비교 기준점입니다.

## devtools

### Bun v1.4.4 — 내장 포매터 bun fmt, bun check 최대 7.8배 속도 개선 (10/22)
Prettier 호환 내장 포매터 `bun fmt`가 추가됐습니다(Prettier 전체 검사 기준 `bun fmt --check` 약 60ms 대 Prettier 약 17초). `bun check`는 대형 프로젝트에서 1.4~7.8배, `-b` 플래그는 프로젝트가 많을 때 최대 15배 빨라졌습니다. `bun install`은 Yarn Berry lockfile 마이그레이션, 요청 실패 시 지수 백오프 재시도, `bun pm fetch`/`cache` 명령을 추가했습니다. 호환성에 영향을 주는 변경으로 glob 패턴 해석 확대(`*(1).txt`, `{1..3}` 등)와 TLS 클라이언트 인증서 요청 동작 변경이 있습니다.

- 출처: [Bun v1.4.4 릴리스 노트](https://bun.com/blog/bun-v1.4.4) · 2026-10-22
- 신뢰도: 높음 (1차 출처, 공식 Bun 블로그)
- 왜 중요한가: 로컬 우선 개발 도구에서 "빌드/포맷 도구를 추가 플러그인 없이 내장"하는 방향은 이 vault가 주목하는 devtools 흐름과 맞습니다. glob·TLS 동작 변경은 호환성에 영향을 주므로, 빌드 스크립트에 Bun을 쓴다면 업그레이드 전 확인이 필요합니다.
