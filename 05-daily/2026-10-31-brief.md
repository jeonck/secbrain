## 오늘 하나만 본다면

Claude Code 2.1.314(10/30)는 `permissions.blockWritesOutsideWorkingDirectories` 설정을 추가해, 모든 권한 모드에서 작업 디렉터리 밖 경로에 대한 Write·Edit·NotebookEdit을 거부할 수 있게 했습니다. [[에이전트-권한-경계-체크리스트]] 핵심 1번("경계는 프롬프트 지시문이 아니라 강제 메커니즘으로 세운다")이 정확히 짚었던 간극 — 이 저장소의 CLAUDE.md가 "`site/`, `scripts/`, `.github/`는 건드리지 마세요"라고 선언만 하고 있던 지점 — 에 하부 메커니즘이 하나 생겼다는 뜻입니다. 지금 당장 이 vault에 켜져 있는지는 확인 범위 밖이지만, 체크리스트가 다음에 반영할 근거로 남겨둘 만합니다.

## anthropic

### Claude Code 2.1.314 — 작업 디렉터리 밖 쓰기 차단 설정, 유휴 압축 추가 (10/30)
`permissions.blockWritesOutsideWorkingDirectories` 설정이 추가돼 모든 권한 모드에서 작업 디렉터리 밖 Write·Edit·NotebookEdit을 거부할 수 있습니다. VS Code·Claude Desktop Code 탭에는 200K 토큰 넘는 유휴 대화를 미리 요약해두는 "유휴 압축" 기능이 들어갔고, 관리자가 effort 수준을 제한했을 때 세션이 "Invalid effort level" 오류로 실패하던 문제와 `claude -p`가 시작 실패 시 조용히 종료 코드 0을 반환하던 문제를 고쳤습니다.

- 출처: [Claude Code 2.1.314 릴리스](https://github.com/anthropics/claude-code/releases/tag/v2.1.314) · 2026-10-30
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스)
- 왜 중요한가: [[에이전트-권한-경계-체크리스트]] 핵심 1번이 요구하는 "정책이 아니라 메커니즘"을, 이 vault가 실제로 쓰는 도구 자신이 플래그로 내놓은 사례입니다. [[secbrain-site]]의 이슈·예약 트리거 파이프라인에 적용할지 검토할 근거로 남겨둡니다.

## agents

### Anthropic, "서브에이전트를 메인 루프로 접을 때" 가이드 공개 (10/22, 구자료)
Anthropic이 공식 블로그에서 여러 전문 서브에이전트 구조 대신, 스킬과 도구를 필요할 때만 불러오는 단일 에이전트 루프가 품질·비용·지연 시간에서 더 나은 경우가 많다고 밝혔습니다. 함께 공개한 참고 구현(`single-agent-loop-kit`, 유지보수 없음)은 "평가 없이는 접지 않는다"는 전제 아래 측정→병합→접기 3단계 절차를 제시하며, 병렬 리서치·독립 검증처럼 서브에이전트를 유지해야 하는 경우도 함께 명시합니다. 7일 신선도 기준(10/24)보다 8일 앞선 자료라 원칙상 제외 대상이지만, 이 vault의 설계 전제와 직접 맞물려 있어 날짜를 밝히고 남깁니다.

- 출처: [Building agents: When to fold subagents into your main agent loop](https://claude.com/blog/building-agents-when-to-fold-subagents-into-your-main-agent-loop) · 2026-10-22, [single-agent-loop-kit 저장소](https://github.com/anthropics/single-agent-loop-kit)
- 신뢰도: 높음 (1차 출처, 공식 Claude 블로그 + 공식 GitHub 참고 구현)
- 왜 중요한가: 이 저장소의 `.claude/skills/*/SKILL.md` 구조([[cog-architecture]])는 애초에 라우터·전문 서브에이전트를 두지 않고, 한 세션이 스킬 지시문을 읽고 vault를 직접 읽고 쓰는 단일 루프 형태입니다. Anthropic의 권고가 뒤늦게 같은 결론("복잡한 멀티 에이전트보다 스킬을 쓰는 단일 루프")에 도달했다는 점은, 이 vault의 설계가 사후 정당화된 사례로 남겨둘 만합니다 — 단, [[cog-architecture]]의 "리드가 판단, 워커가 I/O"라는 비용 분리 패턴은 이 글이 말하는 "항상 함께 실행되는 서브에이전트"와는 다른 축이라, 그대로 겹쳐 읽지는 않습니다.
