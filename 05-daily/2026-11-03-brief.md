## 오늘 하나만 본다면

Claude Code 2.1.317(오늘, 11/3)에 두 가지가 들어갔습니다. 하나는 Agent SDK 훅 콜백이 `onFailure: "block"`을 받을 수 있게 된 것 — 콜백이 실패하면 액션을 막는 옵션입니다. 다른 하나는 `/schedule`이 새 클라우드 예약 작업에 사용자가 요청하지 않은 커넥터가 붙으면 경고하는 기능입니다. 둘 다 [[에이전트-권한-경계-체크리스트]]가 이미 추적하던 선을 따라갑니다 — `onFailure` 기본값이 통과였던 버그(2026-10-09, 핵심 7)의 연장선이고, 커넥터 경고는 "트리거 소스를 최소화한다"(핵심 4)·무인 재실행 안전성(핵심 8)과 같은 축입니다. 다만 이 vault의 파이프라인([[secbrain-site]])은 Claude의 `/schedule`이 아니라 GitHub Actions cron으로 도는 구조라, 두 기능이 이 저장소에 바로 적용되는 건 아닙니다 — 체크리스트의 "하지 말 것" 2번대로, 사례 목록에 날짜만 적어두는 선에서 둡니다.

## anthropic

### Claude Code 2.1.317 — Agent SDK 훅 onFailure:"block", /schedule 커넥터 경고 (11/3)
Agent SDK의 훅 콜백이 `onFailure: "block"` 옵션을 받을 수 있게 돼, 콜백 자체가 실패했을 때 그 실패를 "통과"가 아니라 "차단"으로 처리할 수 있습니다. `/schedule`은 새로 만드는 클라우드 예약 작업에 사용자가 요청하지 않은 커넥터가 포함되면 경고를 띄웁니다. 같은 릴리스에서 셸·웹 도구 호출이 계정 이메일 주소를 네트워크로 보내기 전에 확인을 요구하게 됐고, Claude 앱 게이트웨이에 비용 리포트 엔드포인트(`GET /v1/organizations/analytics/cost`)가 추가됐습니다.

- 출처: [Claude Code 2.1.317 릴리스](https://github.com/anthropics/claude-code/releases/tag/v2.1.317) · 2026-11-03
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스)
- 왜 중요한가: `onFailure: "block"`은 [[에이전트-권한-경계-체크리스트]] 핵심 7("게이트가 있다"와 "게이트가 실제로 버틴다"의 구분)이 2026-10-09 버그 수정 때부터 추적해온 바로 그 설정을, Agent SDK 레벨에서 명시적 옵션으로 만든 사례입니다. `/schedule` 커넥터 경고는 핵심 4(트리거 최소화)·핵심 8(무인 재실행 안전성)과 같은 방향이지만, 이 vault의 예약 실행은 Claude `/schedule`이 아니라 GitHub Actions cron이 거는 구조([[secbrain-site]])라 메커니즘 자체가 겹치지는 않습니다.

### Claude API, Message threads 베타 공개 (11/2)
Messages API에서 긴 대화나 에이전트 루프를 서버 쪽에 두고, 이후 요청에는 새 메시지만 보내는 "Message threads" 베타가 열렸습니다. `message-threads-2026-08-12` 베타 헤더로 켜며, 스레드는 마지막 요청 5분 후 만료되고 마지막 사용 1시간 내에 삭제됩니다. Claude API, AWS·Google Cloud(Anthropic 운영)·Microsoft Foundry 경로에서 제공됩니다.

- 출처: [Claude Platform 릴리스 노트](https://platform.claude.com/docs/en/release-notes/overview) · 2026-11-02
- 신뢰도: 높음 (1차 출처, 공식 플랫폼 릴리스 노트)
- 왜 중요한가: 요청 크기·TTFT를 줄이는 효과는 Messages API를 직접 호출하는 에이전트 루프에 해당합니다. 이 vault의 스킬 실행은 Claude Code CLI(claude-code-action)를 거치는 구조라 이 베타가 바로 적용되는 경로는 아니지만, [[cog-architecture]]가 다루는 "에이전트 루프의 상태를 어디에 두는가" 질문과 같은 방향의 참고 자료로 남겨둘 만합니다.

- 왜 중요한가: [[에이전트-권한-경계-체크리스트]] 핵심 7의 각주가 바로 이 기능을 사례로 들고 있습니다 — 2026-10-11에 "화면에 보이는 명령을 자동 승인하도록 기본값이 완화"된 것으로 처음 기록됐는데, 이번에 실험 모드 제한까지 풀리면서 더 많은 사용자에게 그 완화된 기본값이 그대로 적용되는 범위가 넓어진 셈입니다. 체크리스트의 "하지 말 것" 2번에 따라 정책을 바꾸지는 않지만, 같은 결함 클래스(자동 승인 기본값 완화)가 퍼지는 사례로 추가해둘 재료입니다.
