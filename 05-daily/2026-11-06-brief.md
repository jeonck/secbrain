## 오늘 하나만 본다면

LangGraph 1.2.20(11/5)이 `Command(resume=...)`에 더 이상 유효하지 않은 interrupt ID를 넘기거나, 여러 interrupt가 걸려 있을 때 값 하나만 보내는 경우를 조용히 무시하는 대신 `UnknownInterruptError`로 거부하는 strict resume 모드를 (옵트인으로) 추가했습니다. 기존에는 중복 응답이나 스테일 응답이 아무 신호 없이 버려졌고, 태스크 하나가 여러 interrupt를 호출해도 ID가 같아서 재시도 응답이 다음 질문에 잘못 매칭될 수 있었는데(이번에 interrupt별 ID를 분리해 해결), 둘 다 "멈췄다 다시 돌 때 조용히 틀리게 돌아가는" 패턴입니다. [[에이전트-권한-경계-체크리스트]] 핵심 8은 10/16·10/18 사례 이후 11/3~11/5 브리프에서 계속 "이번 LangGraph 릴리스는 핵심 8과 다른 축"이라고 제외해왔는데, 이번 건은 처음으로 그 축에 정확히 들어맞습니다.

## agents

### LangGraph 1.2.20 — strict resume 모드로 스테일/중복 interrupt 응답 거부, interrupt별 ID 분리 (11/5)
`__pregel_strict_resume`(비공개 configurable 키)을 켜면 pending 상태가 아닌 interrupt ID를 가리키는 resume, 빈 맵, 여러 interrupt가 걸린 상태에서의 단일 값 응답을 그래프가 아무것도 쓰기 전에 `UnknownInterruptError`로 거부합니다. 기존에는 이런 응답이 조용히 버려지고 그래프가 같은 interrupt에서 다시 멈출 뿐이라 클라이언트가 뭔가 잘못됐는지 알 방법이 없었습니다. 같은 릴리스에서 한 태스크 안의 여러 `interrupt()` 호출이 각자 ID를 갖게 되어, strict 모드에서 재시도 응답이 다음 질문에 잘못 매칭되던 구멍도 막았습니다. (정적 breakpoint로 멈춘 경우는 영향 없고, 서브그래프·이미 지나간 체크포인트 재개도 이 검사에서 빠집니다.)

- 출처: [langgraph==1.2.20 릴리스](https://github.com/langchain-ai/langgraph/releases/tag/1.2.20) · [PR #9589](https://github.com/langchain-ai/langgraph/pull/9589) · 2026-11-05
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스·PR)
- 왜 중요한가: [[에이전트-권한-경계-체크리스트]] 핵심 8(재실행 멱등성)이 10/16·10/18 사례 이후 11/3~11/5 브리프마다 "이번 LangGraph 변경은 핵심 8과 다른 축"이라며 반복 제외해온 바로 그 문제(멈췄다 다시 돌 때 조용히 틀리게 처리됨)에 처음으로 직접 해당하는 변경입니다. 옵트인이라 기본값은 그대로 조용히 무시하는 쪽이라는 점은 짚어둘 만합니다.

### OpenAI Agents SDK 0.24.0-alpha.6 — Runner 별칭 제거 등 breaking change, NetworkPolicy·ScriptedResponses 테스트 기능 추가 (11/3, 프리릴리스)
10/15 나온 0.24.0 이후 첫 프리릴리스로, `Runner` 별칭이 제거되고 `Agent.run()`/`run_sync()`로 대체되는 등 호출 방식이 바뀝니다. 네이티브 명령 실행에 `NetworkPolicy`를 적용할 수 있게 됐고, 실제 모델 없이 테스트할 수 있는 `ScriptedResponses`, 단계별 툴 선택·정책 기능도 추가됐습니다. PyPI가 아니라 GitHub 릴리스의 사전 빌드 wheel로만 배포됩니다.

- 출처: [openai-agents-python v0.24.0-alpha.6 릴리스](https://github.com/openai/openai-agents-python/releases/tag/v0.24.0-alpha.6) · 2026-11-03
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스. 다만 알파 프리릴리스라 안정 버전 반영 여부·시점은 확인 불가)
- 왜 중요한가: 11/3~11/5 브리프에서 "OpenAI Agents SDK 11월 신규 릴리스를 찾지 못했다"고 반복 적었는데, 이번 알파가 바로 그 공백을 채웁니다. `NetworkPolicy`는 [[에이전트-권한-경계-체크리스트]] 핵심 1(강제 메커니즘)과 같은 종류의 기능이라 안정 버전으로 올라올 때 다시 확인할 가치가 있습니다.

### Claude 플랫폼 — IP allowlisting(베타), 조직 관리자용 강제 로그아웃 API(베타) (11/5)
API 키가 동작할 수 있는 IPv4/IPv6 주소·CIDR 범위를 조직당 최대 1,000개까지 지정하는 IP allowlisting이 베타로 나왔습니다 — 목록에 없는 주소의 요청은 거부됩니다. 같은 날 Claude Enterprise 조직 관리자가 `POST /v1/organizations/users/{user_id}/sign_out`으로 특정 멤버를 모든 세션·신뢰된 기기·OAuth 토큰에서 강제 로그아웃시킬 수 있는 베타 기능도 추가됐습니다(멤버 자격 자체는 유지, 재로그인 가능).

- 출처: [Claude 플랫폼 릴리스 노트](https://platform.claude.com/docs/en/release-notes/overview) · 2026-11-05
- 신뢰도: 높음 (1차 출처, 공식 릴리스 노트)
- 왜 중요한가: 둘 다 "권한을 가진 주체를 어떻게 좁히고, 문제가 생겼을 때 어떻게 끊어내는가"에 대한 기능이라 [[에이전트-권한-경계-체크리스트]] 핵심 1(강제 메커니즘)과 같은 결입니다. 이 vault는 조직 관리형 API 키나 Enterprise 멤버 구조를 쓰지 않아 직접 해당하진 않지만, API 키를 다루는 다른 프로젝트에 적용할 만합니다.
