## 오늘 하나만 본다면

Microsoft Agent Framework `dotnet-1.28.0`(11/6)에서 가장 눈에 띄는 변화는 두 개의 breaking change입니다. 첫째, 워크플로의 선언적 HTTP 요청이 더 이상 "퍼블릭/프라이빗 IP" 같은 느슨한 분류로 걸러지지 않고, 애플리케이션이 직접 명시한 호스트:포트 allowlist만 통과합니다 — 목록이 비어 있으면 전부 거부되고, 와일드카드·암묵적 서브도메인도 지원하지 않습니다(#9841). 둘째, CodeAct(생성된 코드가 호스트 도구를 호출하는 경로)에서 호스트 쪽 예외 메시지가 기본적으로 생성 코드에 노출되지 않고 리댁션됩니다(#9971/#9973) — 상세 메시지가 필요하면 `include_detailed_errors`를 켜야 합니다. 둘 다 "정책 문구가 아니라 코드가 강제한다"는 [[에이전트-권한-경계-체크리스트]] 핵심 1의 정의에 그대로 들어맞고, 지난주 브리프들이 반복해서 "이번 주는 MS Agent Framework·CrewAI 공식 변경 로그를 못 찾았다"고 적어온 공백을 처음으로 채우는 항목입니다.

## agents

### Microsoft Agent Framework 1.28.0 — HTTP 목적지 명시적 allowlist 강제, CodeAct 호스트 도구 예외 메시지 기본 리댁션 (11/6)
`dotnet-1.28.0`/`python-1.24.0` 계열 릴리스에서 워크플로 HTTP 요청 핸들러가 IP 분류 기반 필터를 버리고, 애플리케이션이 직접 등록한 호스트:포트 allowlist만 통과시키도록 바뀌었습니다. 목적지 검사는 요청 전과 매 리다이렉트마다 다시 수행되고, 워크플로가 보낸 `Host` 헤더는 무시됩니다. 같은 릴리스에서 CodeAct 경로(Python Monty·Hyperlight)는 호스트 도구가 실패했을 때 백엔드 예외 텍스트를 생성된 코드에 그대로 넘기던 것을 멈추고, 기본으로 일반화된 `RuntimeError`만 전달하도록 바꿨습니다(상세 메시지는 옵트인).

- 출처: [microsoft/agent-framework dotnet-1.28.0 릴리스](https://github.com/microsoft/agent-framework/releases/tag/dotnet-1.28.0) · [PR #9841](https://github.com/microsoft/agent-framework/pull/9841) · [PR #9971](https://github.com/microsoft/agent-framework/pull/9971) · 2026-11-06
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스·PR 본문 직접 확인)
- 왜 중요한가: [[에이전트-권한-경계-체크리스트]] 핵심 1("경계는 프롬프트 지시문이 아니라 강제 메커니즘으로 세운다")이 요구하는 정확한 모양 — 네트워크 목적지를 코드 레벨 allowlist로 강제하고, 실패 시 내부 정보를 기본으로 차단합니다. 11/3~11/6 브리프가 반복해온 "MS Agent Framework·CrewAI 공식 변경 로그 공백" 지적이 이번에 처음 채워졌습니다.

### LangGraph SDK 0.4.14 — `strict_resume`을 `runs.create`/`stream`/`wait`에 공개 옵션으로 노출 (11/6)
[[2026-11-06-brief]]가 다룬 LangGraph 1.2.20의 strict resume 모드(비공개 `__pregel_strict_resume` configurable 키로 스테일·중복 interrupt 응답을 거부)가, 하루 뒤 SDK 쪽에 `strict_resume`이라는 공개 파라미터로 노출됐습니다. 같은 릴리스에서 `StreamMode`에 `tools`·`lifecycle` 옵션도 추가됐습니다.

- 출처: [langgraph-sdk==0.4.14 릴리스](https://github.com/langchain-ai/langgraph/releases) · 2026-11-06
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스)
- 왜 중요한가: [[에이전트-권한-경계-체크리스트]] 핵심 8(재실행 멱등성)에 걸리는 기능이 비공개 내부 플래그에서 SDK 공개 API로 승격된 것으로, 클라이언트 쪽에서 이 방어를 켜는 진입장벽이 낮아졌습니다. 여전히 옵트인이라는 점은 그대로입니다.

## devtools

### GitHub Copilot CLI 1.0.107 — 터미널 이스케이프 시퀀스로 화면을 재구성하는 경로 다수 차단, 안정판 전환 (11/6)
프리릴리스 1.0.106 계열에서 쌓인 변경이 1.0.107로 안정판에 합류했습니다. 세션 이름·타이틀·도구 출력·모델이 생성한 텍스트에 섞인 터미널 이스케이프 시퀀스가 화면을 재구성하지 못하도록 막는 항목이 다수 포함됐고, `/session delete`가 알 수 없는 옵션을 거부하고 현재 세션을 실수로 지우지 않게 됐습니다. `/code`로 현재 세션을 VS Code에서 열 수 있는 기능도 새로 생겼습니다.

- 출처: [copilot-cli v1.0.107 릴리스](https://github.com/github/copilot-cli/releases/tag/v1.0.107) · 2026-11-06
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스)
- 왜 중요한가: 모델이 생성한 텍스트나 도구 출력이 터미널을 재구성할 수 있다는 것 자체가 "출력이 신뢰 경계를 넘어 제어 채널이 되는" 사례라, [[에이전트-권한-경계-체크리스트]] 핵심 1이 다루는 강제 메커니즘과 같은 결의 문제입니다.

### GitHub Copilot CLI 1.0.108-0 (프리릴리스) — Assisted Permissions가 거부해도 autopilot이 멈추지 않고 대안을 시도·결과만 보고하도록 수정 (11/7)
GA 상태인 Assisted Permissions는 안전성 검토가 승인을 요구하면 요청을 거부하고 그 설명을 Copilot에 돌려줘 다른 접근을 시도하게 하는 구조입니다(GitHub 공식 문서 확인). 1.0.108-0 변경 로그는 "Autopilot with Assisted Permissions no longer stops for permission prompts. It tries another approach and reports what it couldn't do"라고만 적어, 이전에는 거부 시 autopilot 전체가 멈추던 것을 이번에 고쳤다는 뜻으로 보입니다 — 즉 거부 자체는 그대로 유지되고, 멈추는 대신 계속 진행하며 못한 일을 보고하는 쪽으로 바뀐 것으로 읽힙니다. 다만 프리릴리스 변경 로그 한 줄만으로는 "거부된 요청의 가시성이 보고 시점까지 그대로 유지되는지"는 확인할 수 없었습니다.

- 출처: [copilot-cli v1.0.108-0 릴리스](https://github.com/github/copilot-cli/releases/tag/v1.0.108-0) · [GitHub Copilot CLI 권한 문서](https://docs.github.com/en/copilot/concepts/customizations/allowing-safe-commands) · 2026-11-07
- 신뢰도: 중간 (1차 출처이지만 변경 로그 한 줄뿐이라 거부 시점과 보고 시점 사이의 가시성 변화는 추론)
- 왜 중요한가: [[에이전트-권한-경계-체크리스트]] 핵심 7("게이트가 있다"와 "게이트가 실제로 버틴다"를 구분)이 바로 이런 변경을 점검 대상으로 둡니다. 거부 로직 자체는 안 바뀌었다는 점에서 핵심 7의 과거 사례(Assisted Permissions 기본값 완화, [[2026-10-11-brief]])와는 다른 방향이지만, "멈추지 않는다"는 변화가 거부 이력을 사람이 놓치기 쉽게 만들 가능성은 다음 릴리스에서 실제 동작으로 확인할 필요가 있습니다.

### Claude 플랫폼 — Mythos 5·Opus 4.7·Sonnet 4.6 생성 텍스트에 워터마크 적용 (11/3)

- 신뢰도: 높음 (1차 출처, 공식 릴리스 노트)
- 왜 중요한가: 이 vault가 직접 쓰는 권한·격리 체크리스트와는 다른 축이지만, AI 생성 콘텐츠 판별이 이 vault의 `07-answers/`·브리프 산출물에도 장기적으로 걸릴 수 있는 사안이라 표시해 둡니다.
