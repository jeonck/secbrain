## 오늘 하나만 본다면

Microsoft Agent Framework `python-1.25.0`(11/7)의 가장 중요한 변화는 워크플로 에이전트 실행기(executor)와 세션을 **단일 authorization scope에 묶고, 스코프를 넘어선 실행을 모델을 호출하기 전에 거부**하도록 바꾼 것입니다. 같은 principal이 아니면 `single_user=True`를 쓰지 말라는 경고, 스코프 충돌 시 `WORKFLOW_SCOPE_CONFLICT` 에러 코드, AG-UI 엔드포인트에서 `WorkflowAgent.as_tool()` 자체를 거부하는 것까지 — [[에이전트-권한-경계-체크리스트]] 핵심 1("경계는 프롬프트 지시문이 아니라 강제 메커니즘으로 세운다")이 요구하는 모양을 코드 레벨에서 그대로 구현한 사례입니다. 다만 이 가드는 "살아있는 실행기·세션의 identity"만 커버하고, 공유 스토리지에서 로드된 상태나 워크플로를 호출하는 커스텀 툴 함수는 커버하지 않는다고 릴리스 노트가 명시합니다 — 경계가 어디서 끝나는지까지 적어둔 보기 드문 경우입니다.

## agents

### Microsoft Agent Framework python-1.25.0 — 워크플로 에이전트 실행기·세션을 단일 authorization scope에 바인딩, 스코프 교차 실행 거부 (11/7)
`AgentFrameworkWorkflow(workflow_factory=...)`로 호출마다 새 워크플로·실행기·세션을 만들어야 하며, 공유 빌더는 `cache_target=False`를 줘도 실행기를 재사용한다고 경고합니다. Python 3.10 지원 중단, MCP 디스커버리를 카탈로그당 100페이지·1000항목으로 제한, 선언형 MCP 세션을 핸들러 호출마다 새로 열고 닫도록 바꿔 워크플로 간 상태 공유를 차단하는 변경도 같은 릴리스에 포함됐습니다.

- 출처: [microsoft/agent-framework python-1.25.0 릴리스](https://github.com/microsoft/agent-framework/releases/tag/python-1.25.0) · 2026-11-07
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스 본문 직접 확인)
- 왜 중요한가: [[에이전트-권한-경계-체크리스트]] 핵심 1의 정의("강제 메커니즘")에 정확히 들어맞고, [[2026-11-07-brief]]가 다룬 같은 저장소의 dotnet-1.28.0(HTTP allowlist·예외 리댁션)과 한 주 사이에 연속으로 나온 권한 경계 강화 패턴입니다. 가드의 적용 범위가 "살아있는 실행기·세션"으로 한정된다는 점은 다음에 이 프레임워크를 평가할 때 확인할 포인트로 남깁니다.

## anthropic

### Claude 플랫폼 — 조직용 IP allowlist (베타) 공개 (11/5)
조직 관리자가 IPv4/IPv6 주소나 CIDR 범위(최대 1,000건)를 등록하면, Messages·Batches·Admin API 등 커버 대상 요청이 등록되지 않은 공개 IP에서 오면 403 `permission_error`로 거부됩니다. 다만 Claude Managed Agents 런타임 내부 네트워킹이나 Bedrock·Google Cloud·Microsoft Foundry 경로에는 적용되지 않는다고 문서가 명시합니다.

- 출처: [IP allowlisting 문서](https://platform.claude.com/docs/en/manage-claude/ip-allowlist) · [Claude 플랫폼 릴리스 노트](https://platform.claude.com/docs/en/release-notes/overview) · 2026-11-05
- 신뢰도: 높음 (1차 출처, 공식 문서·릴리스 노트 직접 확인)
- 왜 중요한가: 키 유출 시 피해 범위를 "어디서 쓸 수 있는가"로 줄이는 강제 메커니즘이라 [[에이전트-권한-경계-체크리스트]]의 틀로 바로 읽힙니다. 단, "allowlist는 기간을 제한하지 않으니 키 만료나 Workload Identity Federation을 더 권장한다"는 문서 자체의 경고도 함께 적어둘 가치가 있습니다.

### Claude Enterprise — Admin API로 멤버를 모든 기기에서 즉시 로그아웃 (베타) (11/5)
조직에서 멤버는 유지한 채로 Admin API 호출 한 번으로 모든 기기의 세션을 끝낼 수 있습니다. 멤버는 다시 로그인할 수 있습니다.

- 출처: [Claude 플랫폼 릴리스 노트](https://platform.claude.com/docs/en/release-notes/overview) · 2026-11-05
- 신뢰도: 높음 (1차 출처, 공식 릴리스 노트)
- 왜 중요한가: 계정 탈취·오프보딩 대응 시간을 줄이는 기능으로, IP allowlist와 같은 날 나온 "접근 통제를 관리자가 코드/API로 강제한다"는 흐름의 연장선입니다.

## devtools

이전에는 같은 이름의 커스텀 툴 두 개를 등록하면 모델은 첫 번째 정의를 받지만 일부 SDK는 마지막 핸들러를 실행하는 불일치가 있었는데, 이제 SDK 세션에서 이를 생성·재개·툴 교체 시점에 에러로 막습니다. 또한 인터랙티브 CLI가 로컬 MCP 서버의 환경변수 값을 리터럴로 전달하도록 바뀌어, 호스트 변수를 참조하려면 `${NAME}` 문법을 써야 합니다. Windows용 enumerate-only 디렉터리 권한 설정(`sandbox.userPolicy.filesystem.enumeratePaths`)도 이번에 추가됐습니다.

- 출처: [copilot-cli v1.0.108-0 릴리스](https://github.com/github/copilot-cli/releases/tag/v1.0.108-0) · 2026-11-07
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스 본문 직접 확인)
- 왜 중요한가: [[2026-11-07-brief]]가 같은 버전의 autopilot 변경("권한 거부 시 멈추지 않고 대안 시도")만 다뤘는데, 실제로는 툴 이름 충돌·환경변수 해석처럼 조용히 동작이 바뀌는 항목이 더 있었습니다. "무엇이 바뀌었는지" 변경 로그 한 줄만 보고 넘어가면 놓치기 쉬운 사례라 [[에이전트-권한-경계-체크리스트]] 핵심 7과 겹칩니다.
