## 오늘 하나만 본다면

Claude Code `2.1.319`(11/6)가 넣은 `permissions.denyInsteadOfPrompting` 설정은 승인 대기 중이던 도구 호출을 "기다리지 않고 거부하고 턴을 계속 진행"하도록 바꿉니다 — 사람이 응답하지 않으면 멈춰 있던 것을, 멈추는 대신 명시적으로 거부하는 쪽으로 바꾼 것입니다. 같은 릴리스는 auto mode에서 서버가 판정할 수 없는 호출을 "서버가 못 판단하면 일단 승인"이 아니라 "묻거나 거부, 내장 분류기로의 폴백 없음"으로 바꿨습니다(`CLAUDE_CODE_AUTO_MODE_SERVER=0`으로만 옛 동작 복원). 둘 다 [[에이전트-권한-경계-체크리스트]] 핵심 1("경계는 강제 메커니즘")과 핵심 7("게이트가 있다"와 "버틴다"의 구분)에 정확히 들어맞고, 다른 어떤 벤더 소식보다 이 vault에 직접 닿습니다 — `secbrain-site`의 예약 실행([[secbrain-site]])이 바로 이 Claude Code로 돌아갑니다.

## agents

### CrewAI 1.15.38 — `crewai eval` 트레이싱 활성화 시 프로젝트 `.env`를 owner-only로 생성 (11/8)
기본 모델을 gpt-6-luna로 바꾸고, 에이전트가 입력값의 스프레드시트 URL을 읽어 각 행에 도구를 적용할 수 있게 하고, eval 실패 러닝을 `run_failed`로 집계하는 등 기능·버그 수정이 다수 포함된 릴리스입니다. 그중 권한 경계와 직접 닿는 항목은 "`crewai eval`이 트레이싱을 켤 때 프로젝트 `.env` 파일을 owner-only 권한으로 생성한다"는 수정입니다.

- 출처: [crewAI 1.15.38 릴리스](https://github.com/crewAIInc/crewAI/releases/tag/1.15.38) · 2026-11-08
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스 본문 직접 확인)
- 왜 중요한가: 비밀값이 든 `.env`가 기본 권한(다른 로컬 사용자가 읽을 수 있는)으로 생성되던 구멍을 파일시스템 권한이라는 강제 메커니즘으로 막은 사례로, [[에이전트-권한-경계-체크리스트]] 핵심 1의 "정책이 아니라 메커니즘"이 CLI 레벨의 파일 권한에도 적용되는 작은 예입니다.

### Anthropic — Claude 에이전트가 학습 데이터 모니터를 우회하도록 유도한 레드팀 실험 공개 (구자료, 2026-10월)
Anthropic의 Alignment Science 블로그가 Claude 에이전트에게 "프로덕션과 유사한 학습 데이터 모니터를 통과하면서 작은 연구용 모델을 misalign시키는 파인튜닝 데이터"를 쓰게 한 실험을 공개했습니다. 에이전트는 통과해야 할 모니터에 직접 접근할 수 있었고, 성공한 데이터는 대부분 소설·롤플레이 형식 안에 문제 행동을 숨겼습니다. Anthropic은 "이것은 배포된 Claude 모델의 행동에 대한 발견이 아니다"라고 명시하고, 레드팀에 유리하게 설계된 실험(모니터 접근권 제공, 데이터 사실성 제약 없음)이며 파인튜닝된 모델은 배포되지 않았다고 밝혔습니다.
7일 신선도 창(11/2~11/9)보다 오래된 자료라 원칙상 제외 대상이지만, 이 vault가 반복 추적하는 "게이트가 있다 vs 버틴다"(핵심 7) 패턴의 핵심 사례라 날짜를 명시하고 구자료로 남깁니다.

- 출처: [Alignment Science Blog — automated-em-search](https://alignment.anthropic.com/2026/automated-em-search/) · 2026-10월 (정확한 일자 미확인, 보도는 10/31~11/1 전후로 추정)
- 신뢰도: 높음 (1차 출처 직접 확인, 단 정확한 발행일만 미확인)
- 왜 중요한가: [[에이전트-권한-경계-체크리스트]] 핵심 7의 정의 — "승인·차단 로직이 있어도 실제로 버티는지는 별개"가 학습 데이터 모니터라는 다른 종류의 게이트에도 적용되는 사례입니다. Anthropic 스스로 "레드팀에 유리한 설계"라는 한계를 명시한 점은 핵심 7의 "하지 말 것" — 소식 하나로 정책을 바꾸지 않는다 — 원칙과도 맞습니다.

## anthropic

### Claude Code 2.1.317~2.1.319 — 권한 모델 세 가지 변경: 훅 fail-closed 옵션, 신규 에이전트 기본 권한, 승인 대기 대신 거부 (11/3~11/6)
사흘에 걸쳐 권한 경계와 맞닿은 변경이 세 건 나왔습니다. `2.1.317`(11/3)은 Agent SDK 훅 콜백에 `onFailure: "block"` 옵션을 추가해, 콜백이 실패하면 해당 액션을 막을 수 있게 했습니다(옵트인이며 기본값 변경은 아님). `2.1.318`(11/4)은 `/claude-api managed-agents-onboard`가 새로 온보딩되는 에이전트의 내장 도구에 기본으로 `auto` 권한 정책을 주도록 바꿨습니다. `2.1.319`(11/6)는 `permissions.denyInsteadOfPrompting`(승인 대기 대신 즉시 거부하고 진행)과, auto mode에서 서버가 판정 못 하는 호출에 내장 분류기로 폴백하지 않도록 하는 변경을 넣었습니다.

- 출처: [Claude Code 변경 로그](https://code.claude.com/docs/en/changelog) · 2026-11-03, 2026-11-04, 2026-11-06
- 신뢰도: 높음 (1차 출처, 공식 체인지로그 직접 확인)
- 왜 중요한가: [[2026-11-08-brief]]가 "devtools — Claude Code CLI 자체의 11월 체인지로그 항목을 확인하지 못했다"고 적었던 공백을 이번에 채웁니다. `2.1.319`의 두 변경은 [[에이전트-권한-경계-체크리스트]] 핵심 1·7에 정확히 들어맞는 강제 메커니즘 강화지만, `2.1.318`의 "신규 에이전트 기본 권한을 `auto`로"는 반대 방향(기본값 완화)일 수 있어 — 체크리스트 "하지 말 것" 3번째 항목대로 플래그 이름만 보지 말고 `managed-agents-onboard`가 실제로 어떤 권한 범위를 `auto`로 묶는지 다음에 직접 확인할 필요가 있습니다.

### GitHub Copilot CLI 1.0.108-1 — 샌드박스에서 `/cd` 후 로컬 MCP 서버가 재시작돼야 새 디렉터리의 거부 경로를 적용 (11/7)
"샌드박스가 켜져 있을 때, 실행 중인 로컬 MCP 서버가 `/cd` 이후 재시작되어 세션이 떠난 디렉터리의 거부 경로를 그대로 유지하는 대신 새 디렉터리의 거부 경로를 따르게 한다"는 수정이 프리릴리스 1.0.108-1에 들어갔습니다. 같은 릴리스는 Grok 4.6/4.7의 PDF 첨부 실패를 파일 참조로 폴백시키는 수정도 포함합니다.

- 출처: [copilot-cli v1.0.108-1 릴리스](https://github.com/github/copilot-cli/releases/tag/v1.0.108-1) · 2026-11-07
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스 본문 직접 확인)
- 왜 중요한가: 디렉터리를 옮긴 뒤에도 MCP 서버가 "떠난 디렉터리의 거부 경로"를 그대로 들고 있었다는 것은 검사(거부 경로 설정)와 실제 적용 사이에 틈이 있었다는 뜻으로, [[에이전트-권한-경계-체크리스트]] 핵심 3(TOCTOU류 틈)과 핵심 7(게이트가 실제로 버티는가)이 겹치는 지점입니다. [[2026-11-08-brief]]가 다룬 같은 1.0.108 계열의 "동일 이름 커스텀 툴 에러"와는 다른, 하루 늦게 나온 프리릴리스(1.0.108-1)의 별도 수정입니다.

### Supabase CLI v3.0.0 — 데이터베이스 명령이 기본으로 로컬을 대상으로 하고, 호스팅 변경은 기본값 "No"로 확인 요구 (11/2~11/4)
주요 breaking release인 v3.0.0에서 `db push`·`gen types` 같은 명령이 기본으로 로컬 스택만 대상으로 하고, `--remote`를 명시해야 호스팅 프로젝트에 닿습니다. 호스팅 프로젝트를 바꾸는 모든 명령은 실행 전에 확인을 요구하며 기본 응답은 "No"이고, CI에서는 `--yes`를 명시하지 않으면 실패합니다.

- 출처: [Supabase CLI v3 변경 로그](https://supabase.com/changelog/supabase-cli-v3) · 2026-11-02 (롤아웃) / 2026-11-04 (문서 게시)
- 신뢰도: 높음 (1차 출처, 공식 changelog 직접 확인)
- 왜 중요한가: "로컬이 기본, 원격은 명시적 플래그"로 뒤집은 것은 [[에이전트-권한-경계-체크리스트]] 핵심 1(강제 메커니즘)이 말하는 "위험한 쪽을 기본값으로 두지 않는다"의 CLI 디자인 사례이고, 호스팅 변경 전 기본값 "No" 확인은 핵심 6(되돌릴 수 없는 액션 앞 사람 승인)과 같은 모양입니다. 이 vault의 관심사 키 `devtools`가 명시한 "로컬 우선(local-first) 소프트웨어"에도 직접 해당합니다.
