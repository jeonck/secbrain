## 오늘 하나만 본다면

GitHub Copilot CLI `1.0.110-2`(11/11)는 조직 정책으로 bypass 권한 모드가 꺼져 있을 때 사용자가 `--yolo`나 `--allow-all`을 넘기면, 이전처럼 그 플래그를 **조용히 무시**하고 넘어가는 대신 경고를 띄우도록 바꿨습니다(비대화형 실행에서도 동일). 같은 릴리스는 `/mcp add`·`/mcp edit`가 이미 등록된 이름의 MCP 서버를 덮어쓰지 못하게 막고, 이름이 같은 서버를 설치할 때 기존의 잘못된 설정을 보존하도록 했습니다. 셋 다 [[에이전트-권한-경계-체크리스트]] 핵심 7("게이트가 있다"와 "게이트가 실제로 버틴다"의 구분)에 정확히 들어맞습니다 — 정책이 플래그를 막고 있다는 사실 자체는 전에도 있었지만, 사용자가 "내가 요청한 완화가 적용되지 않았다"는 걸 알 방법이 없었다는 게 그 구멍이었습니다.

## devtools

### GitHub Copilot CLI 1.0.109~1.0.110-2 — 샌드박스·URL 승인·bypass 플래그 관련 변경 묶음 (11/9~11/11)
`v1.0.109`(11/10)는 Linux에서 샌드박스 거부 경로가 그 경로 안의 개발도구 설정 파일 접근도 함께 막도록 범위를 넓히고, 샌드박스 host allow/deny 규칙에 IPv4/IPv6 CIDR 표기를 지원합니다(Claude Fable 5.2를 모델 피커에 추가하는 변경도 같은 릴리스). 반대 방향 변경도 같은 주기에 있었습니다 — 프리릴리스 `1.0.109-0`(11/9)은 URL 권한 프롬프트를 한 번 승인하면 **해당 세션 내 모든 서브도메인**을 함께 승인하도록 완화했습니다. "오늘 하나만 본다면"에서 다룬 `1.0.110-2`(11/11)의 두 변경이 뒤이었습니다.

- 출처: [copilot-cli releases](https://github.com/github/copilot-cli/releases) — [v1.0.109](https://github.com/github/copilot-cli/releases/tag/v1.0.109) · [v1.0.109-0](https://github.com/github/copilot-cli/releases/tag/v1.0.109-0) · [v1.0.110-2](https://github.com/github/copilot-cli/releases/tag/v1.0.110-2) · 2026-11-09 ~ 2026-11-11
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스 본문 직접 확인)
- 왜 중요한가: 같은 사흘 안에 경계를 좁히는 변경(Linux 샌드박스 범위 확대, bypass 무시 경고)과 넓히는 변경(URL 서브도메인 일괄 승인)이 동시에 들어갔습니다 — [[2026-11-10-brief]]가 Claude Code `2.1.321`에서 짚은 "같은 릴리스 안에서 한쪽은 완화, 한쪽은 강화" 패턴이 벤더를 바꿔 반복된 사례입니다. 체크리스트 "하지 말 것" 3번째 항목대로, 플래그·버전 이름만 보고 전체 방향을 판단하면 안 됩니다.

### Zed 1.28.1 — 조직에서 제외된 사용자의 AI 기능이 이전 조직 자격으로 계속 동작하던 버그 수정 (11/11)
사용자가 조직에서 제거된 뒤에도 AI 기능과 edit prediction이 그 조직의 자격으로 계속 동작하던 결함을 고쳤습니다. 릴리스 노트는 이 외의 세부 사항을 밝히지 않았습니다.

- 출처: [Zed 1.28.1 릴리스 노트](https://zed.dev/releases/stable/1.28.1) · 2026-11-11
- 신뢰도: 높음 (1차 출처, 공식 릴리스 노트 직접 확인)
- 왜 중요한가: "권한이 철회됐는데도 메커니즘이 계속 통과시켰다"는 것은 [[에이전트-권한-경계-체크리스트]] 핵심 1·7이 정확히 겨냥하는 결함 모양입니다 — 정책(조직에서 제거)은 선언됐지만 강제 메커니즘(자격 재검증)이 그걸 실제로 반영하지 않았던 사례입니다.

### CrewAI 1.15.40 — AMP가 해석 못 하는 앱을 참조하는 에이전트는 계속 돌지 않고 멈춤 (11/11)
CrewAI AMP(매니지드 실행 환경)가 에이전트가 참조한 앱을 해석할 수 없을 때, 이전처럼 진행을 이어가는 대신 그 에이전트를 멈추도록 바꿨습니다("Stop an agent whose apps CrewAI AMP cannot resolve"). 같은 릴리스는 임베딩 함수 레이어에서 ChromaDB를 제거하고, 행 ID로 과거 상태를 정확히 조회하는 기능과 JSONL을 RAG 데이터 타입 탐색에 연결하는 기능을 추가했습니다.

- 출처: [crewAI 1.15.40 릴리스](https://github.com/crewAIInc/crewAI/releases/tag/1.15.40) · 2026-11-11
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스 본문 직접 확인)
- 왜 중요한가: "참조를 해석 못 하면 일단 진행"에서 "참조를 해석 못 하면 멈춤"으로 바꾼 것은 fail-open에서 fail-closed로의 전환이며, [[에이전트-권한-경계-체크리스트]] 핵심 1·7이 반복해서 요구하는 방향과 같습니다. [[2026-11-09-brief]]가 다룬 같은 저장소의 `.env` owner-only 수정(1.15.38)과 같은 주, 같은 패밀리에서 이어지는 변경입니다.
