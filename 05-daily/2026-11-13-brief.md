## 오늘 하나만 본다면

Claude Code `2.1.323`(11/12)은 MCP 서버 로그인을 마무리하는 도구가 bypass·auto 모드에서도 다시 사용자 확인을 요구하도록 바꿨습니다(아무도 답할 수 없는 `dontAsk` 모드에서는 `/mcp`를 쓰라고 안내). 같은 릴리스는 `PreToolUse` 훅이 "허용"을 반환한 뒤 권한 검사 자체가 에러로 실패하면 "훅이 답하지 않은 것"으로 처리하고, `PermissionRequest` 훅이 입력을 바꿔 쓴 뒤 검사가 실패하면 다시 묻거나(안 되면) 거부하도록 바꿨습니다. 셋 다 [[2026-11-10-brief]]가 짚은 `2.1.321`의 완화("mod가 bypass·auto에서 묻지 않고 자동 활성화")와 정반대 방향이며, 같은 2주 사이클 안에서 Anthropic 자신이 기본값을 다시 조인 사례입니다 — [[에이전트-권한-경계-체크리스트]] 핵심 7("게이트가 있다"와 "버틴다"의 구분)이 벤더 쪽 자기 수정으로도 반복되고 있고, [[secbrain-site]]의 예약 실행이 바로 이 버전 계열로 돕니다.

## anthropic

### Claude Code 2.1.323 — MCP 로그인 확인 복귀, 훅 오류 시 "허용 없음" 처리, 심볼릭 링크 쓰기 우회 차단 (11/12)
"오늘 하나만 본다면"에서 다룬 세 변경 외에, 같은 릴리스는 macOS·Linux·WSL 샌드박스가 다른 곳으로 이어지거나 존재하지 않는 경로로 가는 심볼릭 링크를 통한 쓰기 권한을 더 이상 인정하지 않도록 바꿨고, `git worktree add`·`move`·`remove`와 세션이 시작하지 않은 워크트리에서의 커밋을 샌드박스에서 읽기 전용으로 거부하게 했습니다.

- 출처: [Claude Code 변경 로그](https://code.claude.com/docs/en/changelog) · 2026-11-12
- 신뢰도: 높음 (1차 출처, 공식 체인지로그 원문 직접 확인)
- 왜 중요한가: 심볼릭 링크 쓰기 우회는 [[에이전트-권한-경계-체크리스트]] 핵심 3(TOCTOU류 결함)이 상정하는 정확한 모양이고, 워크트리 커밋 제한은 핵심 1(강제 메커니즘)이 git worktree 레이어까지 넓어진 사례입니다.

### Claude Managed Agents — 셀프호스팅 서비스 전체 출시 (11/12)
기존에는 샌드박스만 자체 인프라에서 돌릴 수 있었던 Managed Agents를, 에이전트·세션·세션 기록 저장까지 포함한 서비스 전체를 자체 인프라에서 운영할 수 있도록 확장했습니다. 모델 요청은 여전히 선택한 제공자(기본값 Anthropic)로 나갑니다.

- 출처: [Claude API 릴리스 노트](https://platform.claude.com/docs/en/release-notes/api) · 2026-11-12
- 신뢰도: 높음 (1차 출처, 공식 릴리스 노트 원문 직접 확인)
- 왜 중요한가: 권한 경계 이슈는 아니지만 세션 기록이 어디 저장되는지를 사용자가 직접 통제하게 된다는 점에서, `anthropic` 키의 범위("Claude·Anthropic 제품 및 API 변경사항")에 직접 해당하는 이번 주기 소식입니다.

## devtools

### GitHub Copilot CLI 1.0.110 — 사전승인된 워크플로 실행 한도를 "사람이 매번 검토한다"고 모델에게 거짓 전달하던 문제 수정, git/ssh/sudo 비밀번호 마스킹 다이얼로그 실험 추가 (11/12)
모든 도구 권한이 사전승인된 워크플로 실행에서도, 그 도구는 모델에게 "사용자가 매 실행의 한도를 검토한다"고 계속 알려주고 있었습니다 — 이번 릴리스는 그 거짓 신호를 없앴습니다. 같은 릴리스는 `/experimental on`으로 켜는 실험 기능으로, 에이전트가 실행한 git·ssh·sudo 명령이 띄우는 비밀번호 프롬프트에 마스킹된 다이얼로그로 답할 수 있게 했습니다.

- 출처: [copilot-cli v1.0.110 릴리스](https://github.com/github/copilot-cli/releases/tag/v1.0.110) · 2026-11-12
- 신뢰도: 높음 (1차 출처, 공식 GitHub 릴리스 본문 직접 확인)
- 왜 중요한가: "사람이 검토한다"는 신호 자체가 거짓이었다는 것은 [[에이전트-권한-경계-체크리스트]] 핵심 7이 정의하는 "게이트가 있다는 착시"의 또 다른 모양입니다. 반대로 비밀번호 마스킹 다이얼로그는 에이전트에게 자격 증명 입력 경로를 새로 열어주는 기능이라, 다음 주기엔 이 경로가 실제로 범위를 좁게 유지하는지 확인할 필요가 있습니다.

## agents

### CrewAI 1.15.41 — SSRF 방지를 유지한 채 사설 IP URL에 정확 호스트명 allowlist 추가 (11/12)
`CREWAI_TOOLS_ALLOWED_PRIVATE_HOSTS` 환경변수로 사설 IP로 해석되는 URL을 호스트별로 허용하는 기능을 추가했습니다. 와일드카드·IP 리터럴은 거부되고, 리다이렉트 재검증과 pinned-peer SSRF 검사는 allowlist에 걸린 호스트에도 그대로 적용되며, `CREWAI_TOOLS_FORCE_SAFE_PATHS`가 켜져 있으면 allowlist 자체가 무시됩니다.

- 출처: [crewAI PR #9178](https://github.com/crewAIInc/crewAI/pull/9178) · [1.15.41 릴리스](https://github.com/crewAIInc/crewAI/releases/tag/1.15.41) · 2026-11-12
- 신뢰도: 높음 (1차 출처, GitHub PR 본문·공식 릴리스 직접 확인)
- 왜 중요한가: "기본은 막혀 있고, 예외는 정확 일치로만 열며, 열어도 리다이렉트 재검증은 유지한다"는 설계가 [[에이전트-권한-경계-체크리스트]] 핵심 1(강제 메커니즘)·핵심 3(검사-실행 사이 틈) 둘 다를 동시에 겨냥합니다 — 권한을 넓히면서도 완화 범위를 호스트명 단위로 좁게 잡은 보기 드문 사례입니다.
